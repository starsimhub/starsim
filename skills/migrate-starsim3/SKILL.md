# Upgrade a Starsim 3 model to Starsim 4

Starsim 4 keeps Starsim 3's module API: a disease written as code (`ss.Infection` with `define_states()`, `set_prognoses()`, `step_state()`), networks, demographics, interventions, connectors, and analyzers all still work, and are a supported way to write a model, not a legacy one. What changed is that Starsim 4 has one vocabulary: where Starsim 4 has its own way to say something, Starsim 3's duplicate spelling was removed rather than kept beside it. So an upgrade is in three steps: make it run (rename what was removed), check the numbers, then, if wanted, use the new tools or declare one disease at a time.

## Workflow

1. **Run the migration script** on the package and its tests: `python -m starsim.migrate mypackage/ tests/` (`--check` lists the changes without writing). It makes the mechanical changes in place (the renames below, the network's name with `ss.PrenatalNet`, a fractional `verbose`, `annualize()`, the bases `ss.SIR`, `ss.SIS`, and `ss.SEIR` of diseases written as code (to `ssl.AgentSIR` and the others), and the time index in `step()`, `update_results()`, and analyzers) and lists, by file and line, what needs a person: work through that list with the tables below, and read the diff.
2. **Run it and fix each remaining error** with the tables below. Every removed name fails loudly (`AttributeError: module 'starsim' has no attribute ...`, or a named error that says what to write instead); nothing removed fails silently.
3. **Check the behavior changes** (the second table): these run without an error but print different numbers. Go through each one that applies to the model.
4. **Validate against Starsim 3**: run the model under Starsim 3 (pin `starsim==3.7.2` in a separate environment) and under Starsim 4 with 10 or more seeds each, and compare the means and spreads of the results you care about (see the validate-import skill for the comparison). Expect them to agree statistically, not bit for bit: the random streams differ, and results are indexed one step differently (below).
5. **Optionally, use the Starsim 4 tools on the unchanged model** (the last section), or port diseases to declared form one at a time (import-model skill, `references/starsim3.md`), validating after each.

## Behavior changes that print different numbers

| What | Starsim 3 | Starsim 4 | What to do |
|---|---|---|---|
| `ss.SIR`, `ss.SIS`, `ss.SEIR` | Written as code, agents only | Declared from states and transitions: any solver, `describe()`, `equations()`, `R0()`; the textbook models, so `dur_inf` and `dur_exp` are exponential (Starsim 3: a lognormal with std 1) and `p_death` is 0 (Starsim 3: 0.01), which changes results (an epidemic is less sharp, with no deaths) | To keep Starsim 3's model (within the timing changes in this table), use `ssl.AgentSIR`, `ssl.AgentSIS`, `ssl.AgentSEIR` (agents only); to keep the declared model, give `dur_inf=ss.lognorm_ex(mean=..., std=...)` and `p_death=0.01`. The migration script flags each use |
| Their results | `n_susceptible`, `n_infected`, `n_recovered`; SEIR `n_exposed`, `n_infectious` | `n_S`, `n_I`, `n_R` (SEIR `n_S`, `n_E`, `n_I`, `n_R`), plus a flow per transition (`infection`, `recovery`, `death`, with its cumulative total as `res.infection.cum`); `new_infections`, `cum_infections`, `prevalence` as before (on `ss.SIR`, `ss.SIS`, and `ss.SEIR` only: a disease declared with `ss.Disease(...)` has just the transition's name, and a data column `new_infections` is matched to its transmission). In flattened tables (`sim.to_df()`) names are lower case: `sir_n_i` | Rename. `sir.infected`, `sir.susceptible`, `sir.recovered` (SEIR also `exposed`, `infectious`, and `infected` as E or I) still work as aliases of the states for this release |
| Their arrays | `sir.ti_infected`, `ti_recovered`, `ti_dead` | `sir.ti_I` (when each agent entered I), `ti_R`, `ti_exit_I` (when they are due to leave) | Rename; deaths from the disease are the flow `sir.results.death` |
| Their keywords | | Accepted as before: `beta`, `init_prev`, `dur_inf`, `p_death`, `dur_exp`; `dur_inf=10` is 10 years (the mean of an exponential); `p_death=ss.bernoulli(p)` is `p`; `init_prev=ss.choose_n(n)` is n agents | `beta` given per network as a dict of bare numbers is a rate per unit time in Starsim 4, but was a probability per step in Starsim 3: for a model with steps shorter than its unit, give `ss.probpermonth(...)` etc. (Starsim 4 warns) |

| Result index | `n_<state>[0]` after the first step | `n_<state>[0]` is the initial state, a flow at index 0 is 0, and `stop=T` takes one step fewer | Compare by time, not by index |
| `self.ti` in code | The step's index, in `step()` and `update_results()` alike | In `step()`, the step's start, as before (so `if self.ti == 0` runs on the first step); in `update_results()` and analyzers, the step's end, where its results go | A result written in `step()` goes at `self.ti + 1`; in `update_results()`, an event dated during the step is at `self.ti - 1` (compared with `self.ti`, it is never found, and the count is 0). The script makes both changes; a run warns about a result of a module written as code that still looks written the old way (a flow at the first time point, or a last point left at 0) |
| A stock written in `step()` (e.g. the size of compartments a module integrates itself) | Recorded after each step | Index 0 is the start, which `step()` never writes | Record stocks in `update_results()`, which also runs at the first time point: `self.results.n_infected[self.ti] = self.I.sum()` |
| A result written in `finish_step()` | Read by the next step's `update_results()` | `finish_step()` runs after `update_results()` at the same time point, so the count is never read | Count it in `step()`, at `self.ti + 1` (the script lists these) |
| An analyzer's `step()` | Called after each step | Also called at the first time point (`self.ti == 0`), before any step, so its results start with the initial state (as `update_results()` does) | If it reads something the first step creates, or collects per-step lists, return early when `self.ti == 0` (the script lists each analyzer) |
| `set_prognoses()` overridden without calling `super()` | `new_infections` was inferred from `ti_infected` (before Starsim 3.6) | `ss.Infection.set_prognoses()` counts `new_infections`; an override that skips it leaves them 0 (a run warns) | Call `super().set_prognoses(uids, sources)`, or `ss.Infection.set_prognoses(self, uids, sources)` to skip a base in between |
| `res.resample('year')` of a stock (`n_alive`) | The mean over the year | The value at the year's end | `kind='ratio'` for the mean |

| `init_prev=20` | An error (use `ss.choose_n(20)`) | 20 people | |
| Many runs (`ss.parallel()`, `ss.MultiSim(...).run()`) | `msim.plot()` drew each sim; `len(msim)` the number of sims; `msim.summarize()` and `msim.compare()` from the sims | `msim.results` holds every result with a run axis first, for any sim; `msim.plot()` draws the median and a 95% interval of each scenario (each sim's label), `lines=True` every run; `len(msim)` is the number of runs; `summarize()`, `compare()`, `diff()`, and `extinction()` work from the results. `msim.sims` still has the sims that were run | Label the sims to compare them as scenarios; `msim.plot(lines=True)` for Starsim 3's picture |

## Starsim 4 tools on the unchanged model

These work on modules written as code, as agents, alongside any declared ones:

- **Modifiers** of the `rel_sus` and `rel_trans` of a disease written as code: `ss.modify(hiv.rel_trans, multiply=0.5, start=2025)`. Its parameters are read by its own code, so they cannot be modified; declare the disease for that.
- **Conditions** on the arrays of a module written as code, written before the sim exists: `where=hiv.cd4 < 200`, `where=hiv.infected & ~hiv.on_art`.
- **Fitting** a parameter of a module written as code: give it as `ss.par` with bounds, and call `sim.calibrate()` (the sim needs `data=`, with columns named like results, e.g. `hiv.prevalence`): `ssl.HIV(beta=ss.par(0.02, bounds=[0.005, 0.1]))`. The module's code sees the plain value.
- **`sim.new()`** rebuilds any sim from what it was made with, with other values or a seed: `sim.new(rand_seed=2)`, `sim.new(pars=dict(beta=0.2))`.
- **Connectors to modifiers**: a Starsim 3 connector that writes `sis.rel_sus[:] = 1.0` and then raises it erases anything else that set `rel_sus` (e.g. the disease's own immunity); `ss.modify(sis.rel_sus, multiply=5, where=hiv.cd4 < 200)` cannot.
- What needs a declared disease, and says so (`E804`): `equations()`, `diagram()`, `R0()`, `stratify()`, and the compartmental solvers (`solver='ode'` and the others). Every MultiSim has results with a run dimension and `msim.diff()`; `msim.extinction()` needs a declared disease.

## Reporting

Say which names were changed (with the table rows used), which behavior changes applied and how the validation came out (means and spreads, Starsim 3 against Starsim 4), and anything that could not be upgraded.
