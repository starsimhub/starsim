# Starsim v3 to v4 migration guide

## Overview

Starsim 4 adds a way to write a disease as declared states and transitions, which can then be run as an ODE, as a stochastic compartmental model, or as agents. This guide maps Starsim 3 code to Starsim 4, job by job, and lists what changes meaning on the way. It is written for both humans and LLMs.

Starsim 3 code is of two kinds, and they migrate differently:

- **Modules written as code** (`ss.Module`, `ss.Infection` subclasses with `define_states()`, `set_prognoses()`, and `step_state()`, custom networks, `ss.Intervention` and `ss.Analyzer` subclasses, `ss.Births`, `ss.Deaths`, `ss.RandomNet`, `ss.MFNet`) are still part of Starsim 4. They run unchanged, as agents, and can sit in the same sim as declared diseases. Per-agent quantities that change continuously (a CD4 count, a level of immunity, time since an event) have no declared form, and keeping them as code is a supported choice.
- **Starsim 3 spellings that Starsim 4 replaces** (the library `ss.SIR`, `ss.SIS`, and `ss.SEIR` as code; `ss.routine_vx`, `ss.campaign_vx`, `ss.routine_screening`, `ss.treat_num`, and the products `ss.Vx`, `ss.Dx`, `ss.Tx`; `ss.seasonality`) have been removed, as have `ss.Calibration` with its components, and `ss.Samples` and `ss.Dataset`. Use the [table of jobs](#jobs-and-spellings) below to port them.

*Note*: If you are an LLM reading this, migrate one module at a time, run the model after each step, compare it with the Starsim 3 results (allowing for the changes in the next section), and confirm with the user before going on.

## What changes the numbers

Read this first: each of these changes results without an error.

### 1. Results move by one step

Results now follow the convention of other modeling frameworks, for modules written as code too. `n_<state>[0]` is the number at the start, before any step; a flow at index 0 is 0; and `n_<state>[ti]` is the number after `ti` steps. A sim with `stop=T` ends at `T`, so it takes one step fewer than in Starsim 3. The same script, with Starsim 3's SIR (`ssl.AgentSIR` in Starsim 4; see 5), gives:

```
                  n_infected[:4]          new_infections[:2]
Starsim 3.7.2     53, 99, 186, 356        26, 46
Starsim 4         31, 53, 94, 168         0, 22
```

(`ss.Sim(n_agents=3000, diseases=ss.SIR(beta=0.1), networks='random')`, with `ssl.AgentSIR(beta=0.1)` in Starsim 4.) The whole curve is one step later, and the random draws differ after that, so results agree statistically (over several seeds), not number for number. For a model with yearly steps, a peak moves a year later. To reproduce published Starsim 3 numbers exactly, use `pip install starsim==3.7.2`.

### 2. Code in a step sees the step's start; results are recorded at its end

During the step from time point `k-1` to `k`, `sim.ti` (and `self.ti`) is `k-1` in every module, as in Starsim 3, so code that does something `if self.ti == 0` does it on the first step. The results of the step are then recorded at `k`: in `update_results()` (and in an analyzer), `self.ti` is `k`. Two Starsim 3 habits need a change, since each otherwise gives a wrong number without an error:

- A result written during `step()` goes at the end of the step, `self.ti + 1`; written at `self.ti`, it lands one index early, on the step's start.
- In `update_results()`, an event dated during the step has a time of `self.ti - 1`; compared with `self.ti`, it is never found, so the count is 0. This is for times set by code written as code; a declared disease dates entry into a state at the step's end (`ti_I == self.ti` in `update_results()` is the people infected during the step just taken).

```python
# Starsim 3
def step(self):
    ...
    self.results.new_cases[self.ti] += len(cases)
    self.ti_dead[dying] = self.ti

def update_results(self):
    super().update_results()
    self.results.new_deaths[self.ti] = np.count_nonzero(self.ti_dead == self.ti)

# Starsim 4
def step(self):
    ...
    self.results.new_cases[self.ti + 1] += len(cases) # At the end of the step
    self.ti_dead[dying] = self.ti

def update_results(self):
    super().update_results()
    self.results.new_deaths[self.ti] = np.count_nonzero(self.ti_dead == self.ti - 1) # Dated at the step's start
```

### 3. A `beta` dict of bare numbers changes meaning

In Starsim 3, `beta=0.05` is a rate per year, but `beta={'randomnet': 0.05}` is a *probability per step*, used as it is. In Starsim 4 both are rates per unit time, so a dict copied verbatim is too low by a factor of about `1/dt`: 12 times at monthly steps, 52 times at weekly ones (5 infections instead of 22,000 in an SIS on a random network at monthly steps). Give each value its Starsim 3 meaning explicitly:

| Starsim 3 (monthly steps) | Starsim 4 |
|---|---|
| `beta={'randomnet': 0.05}` | `beta={'randomnet': ss.prob(0.05, 'month')}` |
| `beta={'mf': [0.008, 0.004]}` | `beta={'mf': [ss.prob(0.008, 'month'), ss.prob(0.004, 'month')]}` |

Use `ss.prob(..., 'week')` or `ss.prob(..., 'day')` for weekly or daily steps. Starsim 4 warns when a dict of bare numbers reaches a declared transmission with a step shorter than its unit; a typed value silences the warning.

### 4. "Routine" delivery means something else

Starsim 3's `ss.routine_vx(prob=0.05, start_year=2005)` gives each eligible person a 5% chance of vaccination *every year*. Starsim 4's routine delivery, `ss.vaccinate(..., coverage=0.05, start='2005')`, offers the vaccine *once*, when a person first becomes eligible. In an SIS model with 5,000 agents from 2000 to 2020, the first reaches about half the population and the second about 5%. The Starsim 3 behavior is delivery in yearly rounds:

```python
ss.vaccinate(ss.Vaccine(efficacy=0.8), coverage=0.05, interval=ss.years(1), start='2005')
```

### 5. A fixed duration becomes exponential

In a disease you declare with `ss.Disease(...)` (or a class with states and transitions), a duration given as a number (`dur=ss.years(1)`) is the mean of an exponential distribution, as in an ODE; `describe()` marks this as a guess. Starsim 3's library diseases used `ss.lognorm_ex()`. To keep a distribution, give it: `I >> R @ ss.lognorm_ex(mean=ss.years(6))`. (A distribution that is not exponential runs as Erlang stages in a compartmental run, with a note.)

This includes the library `ss.SIR`, `ss.SIS`, and `ss.SEIR`, which are now declared, with Starsim 3's keywords but the textbook defaults: `dur_inf` (and `dur_exp`) given as a number or an `ss.dur` is the mean of an exponential (a number is in years, as before), where Starsim 3 had a lognormal with a standard deviation of 1 in the same unit (nearly fixed); and nobody dies of the infection unless `p_death` is given, where Starsim 3 had `p_death=0.01`. The shape matters: an SIR with R0 = 2.5 and a 7-day infectious period, with `beta` cut by 40% from day 30 to 90, infects 715,000 of a million with the exponential and 786,000 with Starsim 3's nearly fixed period. Starsim 3's models, with their defaults, are `ssl.AgentSIR`, `ssl.AgentSIS`, and `ssl.AgentSEIR` (`import starsim.library as ssl`): use them to keep Starsim 3's model, or give `ss.SIR(dur_inf=ss.lognorm_ex(mean=ss.years(6), std=ss.years(1)), p_death=0.01)`.

### 6. Result names follow the states

A declared disease's results are named after its states and transitions: `n_I`, not `n_infected`; the flow of a transition is named after it (`infection`, `recovery`, with the cumulative total `res.infection.cum`); and `ss.SIR`, `ss.SIS`, and `ss.SEIR` have `new_infections`, `cum_infections`, and `prevalence` as before (a disease declared with `ss.Disease(...)` does not; a data column `new_infections` is matched to its transmission). Map the names before comparing with Starsim 3 results.

### 7. Write dates as strings

Write calendar dates as strings (`start='2000'`, `stop='2030-06-30'`), and step sizes with a unit (`dt=ss.months(1)`, not `dt=1/12`). A bare `start=2000` is still read as a year today, but bare numbers are being changed to mean times in the sim's unit.

## Jobs and spellings

Each row is one job, with the Starsim 3 spelling and the Starsim 4 one. In the Starsim 4 column, `sir` is a declared disease and `vaccine` is an `ss.Vaccine`.

### Diseases

| Job | Starsim 3 | Starsim 4 |
|---|---|---|
| Starsim 3's SIR, with its numbers | `ss.SIR(beta=0.1, dur_inf=10)` (a lognormal `dur_inf`, `p_death=0.01`) | `ssl.AgentSIR(beta=0.1, dur_inf=10)`, and `ssl.AgentSIS`, `ssl.AgentSEIR` (agents only); `ss.SIR(...)` is now the textbook SIR, with an exponential `dur_inf` and no deaths |
| An SIR | `ss.SIR(beta=0.1, dur_inf=10, init_prev=0.01)` | `S, I, R = ss.states(3)`, then `infection = S >> I @ ss.peryear(0.1) * I`, `recovery = I >> R @ ss.years(10)`, and `sir = ss.Disease(infection, recovery, init_prev=0.01)` |
| An SIS | `ss.SIS(beta=0.05, dur_inf=10)` | `S, I = ss.states(2)`, then `ss.Disease(infection=S >> I @ ss.peryear(0.05) * I, recovery=I >> S @ ss.years(10), init_prev=0.01, name='sis')` (no waning immunity: add an `R` state and `R >> S` for that) |
| An SEIR | `ss.SEIR(dur_exp=ss.days(5), dur_inf=ss.days(10))` | `S >> E @ beta * I`, `E >> I @ ss.days(5)`, `I >> R @ ss.days(10)` (the state in the rate, `I`, says who infects) |
| A disease given as a dict | `diseases=dict(type='sir', beta=0.1)` | the module itself: `ss.Sim(sir)` |
| Parameters | `define_pars(beta=ss.peryear(0.1))`, `pars=dict(beta=...)` | `beta = ss.par(ss.peryear(0.1), bounds=[0.01, 0.5])`, used in the rate; bounds make it fittable |
| Initial infections | `init_prev=ss.bernoulli(0.01)` | `init_prev=0.01`, or `init=dict(I=100)` for a number; `init_prev=` seeds the state a new infection enters (`E` in an SEIR), and `init=` names the state |
| Population size | `n_agents=10_000` (with `total_pop=` to scale) | `total_pop=1e6` for any solver; `n_agents=` makes `solver='auto'` run as agents (and is used as `total_pop` in a compartmental run if that is not given) |
| A new state, by subclassing | an `ss.Infection` subclass with `define_states()`, `set_prognoses()`, and `step_state()` | a class with states and transitions in its body (below), or keep it as code |
| Moves scheduled with `ti_<event>` | `set_prognoses()` draws `dur_inf`; `step_state()` moves people whose `ti_recovered <= ti` | `I >> R @ dur_inf` (a duration after `@` is a time in the state) |
| Competing exits | `self.transition(uids, to={A: rate_a, B: rate_b})` | one transition per exit: `X >> A @ rate_a`, `X >> B @ rate_b` |
| Death from infection | `p_death=0.01`, drawn at infection | two transitions with the same `dur` and `p=`: `ss.Transition(I, R, dur=dur, p=0.99)` and `ss.Transition(I, ss.null, dur=dur, p=0.01)` |
| A rate scaled per agent | `rel_sus[uids] *= 2` in `step()` | a stratification with `adjust=`, or `ss.modify(sir.rel_sus, multiply=2, where=...)` |

A disease written as a class, when it needs a method as well as transitions:

```python
class SEIR(ss.Disease):
    S, E, I, R = ss.states(4)
    beta     = ss.par(ss.perday(0.3), bounds=[0.1, 1])
    exposure = S >> E @ beta * I
    onset    = E >> I @ ss.days(5)
    recovery = I >> R @ ss.days(10)

seir = SEIR(init_prev=0.01) # Named "seir", after the class
```

### Mixing and demographics

| Job | Starsim 3 | Starsim 4 |
|---|---|---|
| Homogeneous mixing | a `ss.RandomNet()` with many contacts | no network (`ss.Sim(sir)`); this runs as an ODE |
| A contact matrix by age | a custom network or mixing pools | `sir.stratify(age=[0, 15, 65])` and `networks=ss.contacts(matrix, bands=[0, 15, 65])`, or `ss.contacts('Kenya')` |
| A network | `ss.RandomNet()`, `ss.MFNet()`, `networks='random'` | the same; a network makes the sim run as agents |
| Births and deaths | `ss.Births(birth_rate=20)`, `ss.Deaths(death_rate=15)`, or `ss.Sim(birth_rate=20, death_rate=15)` (per 1,000 per year) | for the population: `ss.Sim(demographics=[ss.birth(rate=ss.peryear(0.02)), ss.death(rate=ss.peryear(0.015))])` (per person; under every solver); or keep the modules (agents only). `birth_rate=` and `death_rate=` on the sim are removed |

### Interventions and connectors

| Job | Starsim 3 | Starsim 4 |
|---|---|---|
| A vaccine | `ss.simple_vx(efficacy=0.8)`, `ss.Vx(...)` | `ss.Vaccine(efficacy=0.8)`, which is leaky, as `ss.simple_vx` was by default (everyone vaccinated has their chance of infection cut by 80%); for all-or-nothing (Starsim 3's `leaky=False`: 80% of those vaccinated are fully protected, the rest not at all), `ss.Vaccine(efficacy=0.8, leaky=False)` |
| Routine vaccination, `p` a year | `ss.routine_vx(product=vx, prob=0.05, start_year=2005)` | `ss.vaccinate(vaccine, coverage=0.05, interval=ss.years(1), start='2005')` (see item 4 above) |
| A campaign | `ss.campaign_vx(product=vx, years=[2020], prob=0.6)` | `ss.vaccinate(vaccine, at=['2020'], coverage=0.6)` |
| Who is eligible | `eligibility=lambda sim: sim.people.age < 15` | `where=lambda sim: sim.people.age < 15`, or a condition: `where=sir.age < 15` when `sir` is stratified by age |
| Screening and treatment | `ss.routine_screening(product=ss.Dx(...), prob=0.1)` with a treatment intervention | `screen = ss.screen(ss.Diagnostic(sensitivity=0.9, specificity=0.98), coverage=0.1, interval=ss.years(1))` and `ss.treat(ss.Treatment(cure=0.95), who=screen.positive, coverage=0.8)` |
| Treatment with limited capacity | `ss.treat_num(product=ss.Tx(...), max_capacity=10)` | `ss.treat(ss.Treatment(cure=0.95), on=sir.infection, capacity=10)` |
| A parameter change at a time | an `ss.Intervention` that edits `sim.diseases.sir.pars.beta` in `step()` | `ss.change(sir.pars.beta, at=['2010'], by=[0.5])` |
| A change while something holds | the same, with a test in `step()` | `ss.modify(sir.pars.beta, multiply=0.6, start='2020-03-15', stop='2020-06-01')` |
| Seasonality | `ss.seasonality(...)` | `beta=ss.seasonal(mean=ss.peryear(0.5), amplitude=0.4, peak='January')` |
| One disease changing another | an `ss.Connector` that writes `sis.rel_sus` from `hiv`'s states | `connectors=ss.modify(sis.rel_sus, multiply=3, where=hiv.I)` |
| A custom intervention | an `ss.Intervention` subclass with `step()` | keep it (agents), or `ss.vaccinate(..., deliver=fn)` with a function returning who receives it |

A connector that sets an array (`sis.rel_sus[:] = 1.0`, then raises it for some people) also erases what other modules set, such as a disease's own immunity. `ss.modify()` multiplies a base value that it never overwrites, so modifiers from several modules combine.

### Runs, results, and calibration

| Job | Starsim 3 | Starsim 4 |
|---|---|---|
| Many runs of one sim | `ss.MultiSim(sim, n_runs=10).run()`, then `msim.mean()` | `msim = sim.run(n_runs=10)` (or `ss.parallel(sim, n_runs=10)`), then `msim.results.sir.n_I.median()` or `.quantiles()`, for any sim; `msim.reduce()`, `mean()`, and `median()` are gone |
| Scenarios | `ss.parallel(sim1, sim2)` | `ss.parallel(baseline=sim1, masks=sim2)`, and `msim.diff('baseline')` |
| A parameter sweep | a loop over `ss.Sim(pars=...)` | `ss.parallel(sim, pars={'sir.beta': [0.2, 0.3, 0.4]})` |
| A result | `sim.results.sir.n_infected` | `sim.results.sir.n_I` |
| A result by group | an analyzer | `sim.results.sir.n_I.by('age')`, `.select(age='0-14')` |
| A copy with changes | `sc.dcp(sim)`, then edit | `sim.new(solver='abm', n_agents=5000)` |
| Calibration | `ss.Calibration(sim, calib_pars=dict(beta=dict(low=0.01, high=0.3, guess=0.1)), build_fn=..., components=[ss.Normal(...)], total_trials=100)`, then `calib.calibrate()` | `beta=ss.par(0.1, bounds=[0.01, 0.3])` in the model, `ss.Sim(sir, data=df)` with a column named after a result (`prevalence`), then `fit = sim.calibrate()` (`trials=100` for Optuna, used for agents) |
| A likelihood | `ss.Normal(...)`, `ss.BetaBinomial(...)` components | `sim.calibrate(likelihood=dict(prevalence=ss.normal(scale=0.02)))`, or `likelihood=` on an `ss.outcome()` |
| Data shared by two diseases | an `extract_fn` per component | name the column after the disease too: `sis.prevalence` |

## Migrating one disease at a time

A published model does not have to move all at once. Keep the hard disease as code and declare the easy one: the mixed sim runs as agents, and one declared disease is enough for `sim.new()`, `ss.parallel()` scenarios and sweeps, `msim.diff()`, and `sim.calibrate()` to work on the whole sim.

```python
import starsim as ss
import starsim.library as ssl

hiv = ssl.HIV(beta={'mf': [0.008, 0.004], 'random': 0}, init_prev=0.05) # Unchanged Starsim 3 module
S, I = ss.states('S I')
sis = ss.Disease( # Newly declared
    infection = ss.Transition(S, I, rate=ss.par(ss.prob(0.005, 'month'), bounds=[0.001, 0.05]) * I),
    recovery  = ss.Transition(I, S, dur=ss.years(2)),
    init_prev = 0.05,
    name = 'sis',
)
susceptible = ss.modify(sis.rel_sus, multiply=3, where=lambda sim: sim.diseases.hiv.infected)
sim = ss.Sim([hiv, sis], networks=[ss.MFNet(), ss.RandomNet()], connectors=susceptible,
             n_agents=2000, start='2000', stop='2020', dt=ss.months(1))

vaccine = ss.vaccinate(ss.Vaccine(efficacy=0.8), disease=sis, coverage=0.05, interval=ss.years(1), start='2010')
msim = ss.parallel(baseline=sim.new(), vaccine=sim.new(interventions=vaccine), n_runs=3)
msim.diff('baseline')
```

Two things to know in a mixed sim:

- A condition on a module written as code is a function of the sim (`where=lambda sim: sim.diseases.hiv.infected`); `where=hiv.infected` works only for declared diseases.
- `ss.modify()` and `ss.vaccinate()` act on declared diseases (give `disease=` when there are several). They do not reach a module written as code; keep its Starsim 3 connectors and interventions until it is ported.

To validate each step, run the Starsim 3 version and the ported one over several seeds (`sim.run(n_runs=10)`) and compare means and spreads, after mapping the result names and allowing for the one-step shift.

## What needs a declared disease

| Works on any module | Needs a declared disease |
|---|---|
| Running as agents, networks, `ss.Births`/`ss.Deaths`, analyzers, `ss.parallel(sim, n_runs=...)` with `msim.results` across the runs, `sim.describe()` (in brief) | The ODE and stochastic compartmental solvers, `describe()` in full, `equations()`, `sim.new()`, scenarios and sweeps with `ss.parallel()`, `sim.calibrate()`, `ss.modify()` and `ss.vaccinate()` targets, `msim.extinction()` |

A sim with at least one declared disease gets the tools in the second column, for the sim as a whole.
