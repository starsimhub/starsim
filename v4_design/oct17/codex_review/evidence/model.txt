P2: Lazy condition contract incomplete. design/07-effects.md:175-178 promises comparisons, logical operators, arithmetic, and .isin are lazy before initialization. arrays.py:453 implements lazy boolmath, but numeric _math at :554-605 immediately indexes raw and isin at :517-552 immediately computes. P2: Modified array reads differ from the promised API and expose different values to extension code. arrays.py:915-930 explicitly gives base on ordinary read and .effective on model reads; design/07-effects.md:85 promises ordinary reads give effective, and :108 promises in-place operations act on base. best-practices/composition-and-effects.md:143 also promises effective reads, but :163 says in-place operators double-count (a disagreement with final design). Existing extension code reading rel_sus can disagree with transmission. Recommendation: settle one public contract and make both implementation and documents/examples reflect it. Explicit base/effective accessors are simpler than special get/set/in-place magic: e.g. quantity.base[uids] for mutation and quantity.effective[uids] for reads, with ordinary array semantics well-defined. If adopting effective ordinary reads, specifically test Python indexed augmented assignment and aliases; it is not solved by overriding only __imul__.

Structural simplification recommendations:
1. Build one immutable validated model/value representation at the declaration-to-engine boundary. State, parameter, grouped value, unit conversion, and modification semantics should not be reinterpreted independently by solver variants. Current early-return bug is the predictable cost of divergent value paths.
2. Separate normalization from inference. Positive population weights may reasonably normalize, but invalid negatives/NaNs never should. Keep guessed defaults inspectable, while errors remain early and specific.
3. Reduce interchangeable spellings. Tests exercise string transitions, operators, explicit constructors, class forms, and positional/keyword variants. Choose one beginner-facing spelling and teach it end-to-end; keep other forms as advanced adapters to the canonical model, not competing primary interfaces.
4. Prioritize a small contract matrix over individual feature tests: values (scalar/callable/time series/grouped/typed), solver families, modifiers, and initialization/override behavior. Same semantic input must have same scientific meaning in every permitted representation. Add regression tests above, including rejection tests. Comprehensive feature volume is less valuable than cross-feature contracts.
5. Docs should distinguish normative specification from exploratory best-practice discussion. The augmented-assignment contradiction is one concrete example of advice becoming stale as design decisions change. Maintain normative decisions once, with best-practice rationale linking there and executable examples checked against implementation.
