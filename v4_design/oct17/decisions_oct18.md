## Model behavior

10. **`ss.SIS`** is the textbook SIS, with no immunity (the Starsim 3 baseline SIS, which had waning immunity, gives 13% more infections). Recommendation: keep the textbook form. [CK: ok, but port the existing form too, it can be `ssl.SIS_waning` or similar]
11. **A sim of declared modules with no `start`** runs from year 0, not 2000. Recommendation: keep (no calendar unless one is given). [CK: ok]
12. **When infections are dated.** A declared disease dates entry into a state at the end of the step, code at the start (documented in the docs and the migration guide). Recommendation: keep, documented. [CK: no, they should match -- i think you said convention among other libraries was the end of the step, so let's follow the convention even if it changes the results]
13. **`sim.people` in a compartmental run** is a one-row `People` (not `None`, as this file first said). Recommendation: keep; the try-it rule makes functions of people raise with a pointer to agents. [CK: not sure about one row ... seems like it could be used for compartments, metapopulations, etc. but i would need to see the alternatives in more detail.]
14. **`ss.Births`, `ss.Deaths`, `ss.Pregnancy` rates.** They take rates per 1,000 by default. Per person would match the declared `ss.birth`/`ss.death`, but would silently multiply births by 1,000 in downstream models. Recommendation (D28's): per person, with an error for a bare number above 1. [CK: hm, i think i prefer per 1000 since that's convention. i think the `unit=1000` argument (i forget exactly what it's called) handles this, but needs to be clearly documented. i just think people would prefer to type `ss.births(35)` than `ss.births(0.035)`. maybe could give a warning if <1 and suggest setting `unit=1`. or, i know you didn't like this before, but have `unit=None` by default, and assume per 1000 if >1, and per 1 if <1, and print a warning if anything is ambiguously large or small and no `unit` is explicitly given.]
15. **Conveyors for other dwell times.** A lognormal or Weibull dwell time with a short support could be a conveyor of whole steps (exact at the step) instead of Erlang stages (approximate in shape). It would change results for ordinary models. Recommendation: not for 4.0. [CK: this sounds useful, but what's the problem with it? would it add a lot of code?]
16. **`auto` and a per-step function that reaches for agents later** (FIX's claim 2). Such functions are tried on groups at the first step; one that only needs agents later (the spec's `seed_cluster` at `sim.ti == 30`) passes, so `auto` picks the ODE, and the run stops at that step with a `CapabilityError`, not silently. The alternative is to run any per-step function as agents without trying it. Recommendation: keep the trial. [CK: ok]

## Solvers and fitting

17. **The event limit for tau leaps.** `solver='gillespie'` takes tau leaps when the counting ODE run gives more than 1e6 events. At 16,000 herds that is 6.2e6 (exact by place: build 2.0 s, run 1.7 to 3.1 s; tau leaps: 5.8 s and 8.4 s). A crossing's event costs 7 to 30 µs, so at the limit an exact crossing run takes about 25 s. Recommendation: a separate, larger limit for runs by place (N26), the limit in events otherwise (CROSS). Also JAX from 300 runs (S's threshold). Now: 1e6 everywhere. [CK: um ... ok, i don't care too much]
18. **Agents' exponential `dur=` against `rate=`** (X7, Decision lang 17). As agents, an exponential `dur=` is sampled as a duration, while `rate=` is drawn as a hazard each step, so the declared equivalence of the two holds only approximately, and seeded people leave a step late. Options: realize exponential dwells as a hazard (changes agent results), or keep sampling and state the difference. Recommendation: realize them as a hazard. (The chain binomial at a daily step, X4, you left to me: it keeps whole steps and reports the size of the effect.) [CK: ok]
19. **Nelder-Mead for one or two parameters** (R25). The default uses L-BFGS-B whenever there are gradients (1.2 to 1.6 s against Nelder-Mead's 0.15 s for one or two parameters). Recommendation: Nelder-Mead up to two parameters. [CK: ok]
20. **How a stochastic fit scores a point** (W13): the mean of the runs' errors (now) or the error of the runs' mean, and how many runs. With four runs a point, a small EpiModel fit is off by about 3.5 points of prevalence on average; ten runs halve that. Recommendation: keep the mean of errors and raise the default to ten runs for agent fits. [CK: ok]
21. **Memory per agent** (N25): 125 bytes now, against a target of about 50. Getting there needs 16-bit timers (changes results) or dropping public arrays (`ti_X`, `scale`, `ti_removed`). Recommendation: `ti_X` as int32 step numbers, keeping exit times float32 (saves about 20 bytes, results unchanged for whole-step times). [CK: i'm ok with 16-bit timers, especially if that would be faster as well. also it seems np.bool is crazily inefficient when uint8 would do, am i wrong? int32 step numbers work too i guess, although if they're used in calculations i'd be worried users would do something dumb, so the conversions should be fast, obvious, and correct.]
22. **Writes that bypass the kept counts.** Writing to `mod.I.raw` directly skips the count hook (nothing in Starsim does it; `STARSIM_CHECK_COUNTS=1` catches it). Recommendation: accept, documented. [CK: ok]
23. **`ss.parallel()` forks a process that already has threads** (W17). No hang has been seen. Recommendation: start workers with `forkserver` once JAX or Numba's threads are loaded. [CK: ok]
