# The intermediate representation

What a compiled model is, as data. Everything the language claims — checking, stratification, diagrams, ODE generation, hashing, translation, prose-to-model determinism — is a function of this structure.

Justified by [best-practices/model-structure.md](../best-practices/model-structure.md) and [best-practices/principles.md](../best-practices/principles.md) §AI-native.

## Purpose

Three independent designs in the landscape reached the same requirement by different routes — a topologically sorted equation set, a compiled dependency DAG, and a flat compiler IR. **Whatever the surface syntax, the model must become a graph before it becomes a computation.**

The IR is that graph. It is:

- **complete** — a backend needs nothing else;
- **canonical** — semantically identical models produce byte-identical IR;
- **serializable** — JSON, with no Python objects;
- **the hashing surface** — model identity is the hash of a slice of it;
- **the translation surface** — import and export ([16-interop.md](16-interop.md)) map to and from IR, never to and from model text.

The IR is not an authoring format. An interchange format that nobody authors in becomes a lossy export target, and partial conformance becomes the normal state; the authoring language is the artifact and the serialization is derived. `ss.load()` accepts IR because round-tripping must work, not because anyone should write it.

## Structure

```json

  "modules": [
    {
      "name": "sir",
      "kind": "disease",

      "phase": "main",
      "states": [
        {"name": "S", "init": {"kind": "frac", "value": 1.0}, "infectious": false,
         "rel_sus": 1.0, "rel_trans": 1.0, "inferred": ["name", "init"]},
        {"name": "I", "init": null, "infectious": true,
         "rel_sus": 1.0, "rel_trans": 1.0, "inferred": ["name", "infectious"]},
        {"name": "R", "init": null, "infectious": false,
         "rel_sus": 1.0, "rel_trans": 1.0, "inferred": ["name"]}
      ],

         "src": ["S"], "dst": ["I"], "p": null,
         "beta": {"kind": "rate", "value": 0.05, "unit": "day"},
         "source": ["I"], "route": null, "scale": null,
         "inferred": ["source", "beta.unit"]},
        {"name": "recovery", "kind": "progression",

  "routes": [
    {"name": "mixing", "kind": "Homogeneous", "layer": null,
     "n_contacts": 10.0, "dependence": "frequency", "n_ref": null,
     "inferred": ["kind", "n_contacts", "dependence"]}
  ],
  "effects": [],
  "config": {
    "method": "abm", "start": "2020-01-01", "stop": "2021-01-01",
    "dt": {"kind": "dur", "value": 1.0, "unit": "day"},

    "rand_seed": 0, "crn_key": "slot", "unit": "day"
  },

  }

```

Every field is present in every IR document; absent values are `null`, never omitted. This makes the schema fixed-shape, which makes diffing legible and makes a consumer's job smaller.

## The `inferred` list

Every object carries `inferred`: the list of its own fields whose values were guessed rather than given. This is what `summary()` prints, and it is what makes aggressive default-guessing auditable rather than hidden.

`inferred` participates in the model hash. Two models that differ only in whether a value was written down or inferred are the *same model* and must hash the same — so the hash is computed over resolved values, and `inferred` is carried in `meta` for display. See §Hashing below for the precise slice.

## Expressions

Expressions — predicates, characteristics, and rate expressions — are encoded as prefix lists. No strings containing expressions appear anywhere in the IR.

```json
["and", ["gt", ["attr", "age"], 65], ["not", ["state", "sir", "vaccinated"]]]
```

| Head | Arity | Meaning |
|---|---|---|
| `attr` | 1 | a built-in agent attribute: `age`, `sex`, `uid` |
| `state` | 2 | module, state or dimension coordinate |
| `result` | 2..3 | module, result name, optional window |
| `par` | 2 | module, parameter name |
| `time`, `year`, `weekday`, `date` | 0..1 | model-level observables |
| `has` | 1 | holds a named product |
| `scheduled` | 1 | has a pending named transition |
| `and`, `or`, `not` | n, n, 1 | logical |
| `gt`, `lt`, `ge`, `le`, `eq`, `ne` | 2 | comparison |
| `add`, `sub`, `mul`, `div` | 2 | arithmetic |
| `isin` | 2 | membership |
| `opaque` | 1 | an escape-hatch callable, identified by a content hash of its bytecode |

Every expression node carries a computed `rank` (`scalar`, `group`, or `agent`) in the compiled form, which is what the capability matrix consumes ([12-backends.md](12-backends.md)).

`opaque` is how the IR stays complete in the presence of escape hatches: the callable cannot be serialized, so the IR records its hash and its declared reads and writes, and every backend that cannot execute Python refuses on that node by name.

## Quantities

```json
{"kind": "rate", "value": 0.05, "unit": "day"}
{"kind": "dur",  "value": 10.0, "unit": "day"}
{"kind": "prob", "value": 0.1,  "per":  {"kind": "dur", "value": 1.0, "unit": "day"}}
{"kind": "freq", "value": 2.0,  "unit": "week"}
{"kind": "count","value": 500}
```

Distributions:

```json
{"dist": "lognorm", "mean": {"kind": "dur", "value": 10.0, "unit": "day"},
                    "std":  {"kind": "dur", "value": 3.0,  "unit": "day"}}
{"dist": "erlang", "k": 3, "mean": {"kind": "dur", "value": 10.0, "unit": "day"}}
```

Shaped values:

```json
{"by": ["age"], "shape": [3], "values": [0.08, 0.05, 0.03]}
{"by": ["patch", "patch"], "shape": [47, 47], "ref": "data/mobility.npz#sha256:..."}
```

Large arrays are stored by content-addressed reference rather than inline, so that an IR document stays readable and a hash stays cheap.

## Normalization

Normalization is what makes the IR canonical. It MUST be idempotent, and it MUST be applied before hashing, comparison, or serialization.

1. **Resolve.** Every inferred value is materialized. Nothing in the IR depends on inference rules being re-applied by the consumer.
2. **Type.** Every bare number becomes a typed quantity with an explicit unit.
3. **Unit.** Every quantity is converted to the model's base unit — days for time, unless the model's `unit` is coarser, in which case that. `datedur` values keep their calendar form, because they are not convertible without a reference date.
4. **Expand.** Arrows become `src`/`dst` lists. Sugar (`ss.change`, `ss.vaccinate`, dict shorthand) is expanded to the constructs it stands for.
5. **Sort.** Modules by name; declarations within a module by `(kind, name)`; expression operands of commutative heads (`and`, `or`, `add`, `mul`) by their serialized form; keys of every object lexicographically.
6. **Strip.** Labels, docs, sources, ontology annotations, and provenance move to `meta`.
7. **Round.** Floating-point values are serialized with `repr` round-trip precision, never truncated.

After normalization, the three construction forms of the same model ([01-objects.md](01-objects.md)) MUST produce byte-identical documents. This is the form-equivalence conformance test.

## Hashing

```
model    = SHA256(canonical(modules + routes + effects + scenario.enabled_structure))
pars     = SHA256(canonical(all resolved values + data references with versions))
config   = SHA256(canonical(config))
scenario = SHA256(canonical(scenario))
fit      = SHA256(canonical(fit)) or "none"
```

Rules:

- The `model` hash covers **structure**: states, transitions and their kinds, dimensions, routes and their conventions, effects and their combiners, outcome structure, and the likelihood *form*.
- The `pars` hash covers **values**: every number, every distribution parameter, every likelihood nuisance parameter, and the source, version, and retrieval date of every fetched dataset.
- `meta` never contributes to any hash. Renaming a label does not change a model.
- The two-way split MUST be strict: changing a rate changes `pars` and not `model`; changing a rate to a duration changes `model`, because the declaration is structurally different even when the dynamics are identical.

The last rule is a deliberate choice against maximal semantic canonicalization. `dur=ss.days(10)` and `rate=ss.perday(0.1)` produce identical *dynamics*, and the IR records the same `dwell` object for both, so in fact they hash the same. Where a normalization is cheap and total, it is applied; where it would require solving an equivalence problem, it is not, and the failure mode is a spurious hash difference rather than a spurious hash collision.

## Versioning

`schema` is `lingua-franca/MAJOR.MINOR`.

- A **minor** bump may add optional fields. A consumer MUST ignore unknown fields within its major version.
- A **major** bump may remove or repurpose fields, and MUST ship a mechanical upgrade path.
- A document whose major version exceeds the reader's raises `E1401 SchemaTooNew` and names the version required.
- A backend MUST declare which schema versions it consumes.

## Serialization

```python
sir.to_dict()                       # the IR as a Python dict
ss.save(sir, 'model.json')          # canonical JSON
ss.save(sir, 'model.sbml', format='sbml')
ss.load('model.json')               # back to a model object
```

Round-trip requirements, both normative and both conformance tests:

1. `load(save(m))` MUST produce a model whose normalized IR is identical to `m`'s.
2. `normalize(normalize(x)) == normalize(x)`.

Lossy exports ([16-interop.md](16-interop.md)) MUST report what was dropped, at the granularity of a declaration:

```text
ss.save(model, 'model.sbml')
  ! dropped: ss.SexualNet route (no SBML representation)
  ! dropped: 2 effects with agent-rank conditions
  ! approximated: lognormal dwell time on 'recovery' -> Erlang(k=2)
  kept: 3 states, 2 transitions, 1 dimension
```

## Why this is the AI-native surface

The project's framing goal is that a model description in prose maps deterministically to a specification. That requires four things, and the IR supplies three of them:

1. **The model is data, so a generated model can be checked** before it is run, against the rules in this folder rather than against a human reviewer.
2. **A canonical printed form**, so that two agents given the same prose produce the same document — determinism is testable because normalization exists.
3. **A complete, versioned, fixed-shape schema**, so that a generator has a target rather than a style.
4. The fourth is not the IR's job: **documentation shipped with the version, offline and doc-tested**, so that a generator reading stale documentation does not write broken models. That is a release requirement, recorded in [18-conformance.md](18-conformance.md).
