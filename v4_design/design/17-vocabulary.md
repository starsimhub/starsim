# The complete vocabulary

Every public name in the language, in one place, with a count.

Justified by [best-practices/principles.md](../best-practices/principles.md) §8: *a feature that only pays off in one framework's use case does not go in — bloat is a correctness problem, because a vocabulary nobody can hold is a vocabulary nobody uses correctly.*

This document exists so that the total is visible. Starsim's own review names its surface area as a signal about the specification burden rather than a solution to it; a language that intends to be smaller has to be able to prove it.

## Base classes and returned types — 9

`ss.Route` · `ss.Intervention` · `ss.Transition` · `ss.Result` · `ss.Expr` · `ss.Dist` · `ss.Loop` · `ss.Timeline` · `ss.Fit`

Users subclass these or receive them from a call; they are rarely constructed directly. `ss.Base`, `ss.Declaration`, `ss.Quantity`, and `ss.Dimension` are internal and are not counted, because nothing in the documented language requires naming them.

## Transitions — 6

`ss.transmission` · `ss.progression` · `ss.birth` · `ss.death` · `ss.transfer` · `ss.process`

**Closed.** A seventh requires removing one. This closure is what makes stratification, ODE generation, and format translation possible: the compiler can transform a transition only if it knows what the transition means.

## Time and rates — 21

Four families × five units, plus `datedur`:

| Family | Units | Names |
|---|---|---|
| duration | hour, day, week, month, year | `ss.hours` `ss.days` `ss.weeks` `ss.months` `ss.years` |
| rate (hazard) | same | `ss.perhour` `ss.perday` `ss.perweek` `ss.permonth` `ss.peryear` |
| probability per period | same | `ss.probperhour` `ss.probperday` `ss.probperweek` `ss.probpermonth` `ss.probperyear` |
| frequency (count/time) | same | `ss.freqperhour` `ss.freqperday` `ss.freqperweek` `ss.freqpermonth` `ss.freqperyear` |

Plus `ss.datedur`, for calendar arithmetic that float years get wrong.

This is the largest single block in the language and the one most at risk of being called bloat. The defense is that it is **generated by two orthogonal choices** — which of four kinds, which of five units — so it is two decisions to hold, not twenty-one names to memorize, and the four kinds are the ones five independent framework designs arrived at in five different media. The constraint that follows: **no new time family, and no new unit.** If a new one seems necessary, check whether it is a `datedur` in disguise.

## Distributions — 12

`ss.bernoulli` · `ss.uniform` · `ss.normal` · `ss.lognorm` · `ss.expon` · `ss.gamma` · `ss.erlang` · `ss.poisson` · `ss.binomial` · `ss.weibull` · `ss.neg_binomial` · `ss.dist`

**Closed at eleven named distributions plus the escape hatch.** `ss.dist(scipy_frozen)` covers everything else and reports reduced capability where a closed form is needed. A twelfth named distribution requires removing one.

## Interventions — 7

`ss.Vaccine` · `ss.Test` · `ss.Treatment` · `ss.vaccinate` · `ss.screen` · `ss.treat` · `ss.change`

Three products, three deliveries, one piece of sugar. `ss.Effect` does the rest and is counted under core objects. Routine versus campaign is a keyword, not a class; a Cartesian product of delivery mode × product type spelled out as classes is the specific vocabulary growth this language rejects.

| **Total** | **134** |

Of which a user writing an SIR touches **nine**: `ss.Disease`, `ss.transmission`, `ss.progression`, `ss.days`, `ss.Sim`, `run`, `plot`, `summary`, and one route. A user writing a stratified, calibrated, intervention-bearing national model touches perhaps forty.

The distribution matters more than the total. The design target is that the **first model costs under ten names** and each additional capability costs one or two, with no cliff where a user has to learn a second system. That is what the [equivalence rule](01-objects.md#the-equivalence-rule) protects: there is no second system to fall into.

## The budget

Normative:

1. **Four sets are closed**: transitions (6), time families (4), distributions (11 + escape hatch), effect targets ([07-effects.md](07-effects.md)). Adding to any of them requires removing from it, in the same change, with the reasoning recorded.
2. **A new name must pay for itself across at least two framework use cases.** A feature that serves one framework's speciality is a feature that belongs in that framework.
3. **A new name must not be reachable by an existing composition.** A bednet is not a class, because it is an effect. A junction is not a state kind, because it is a branching arrow. A metapopulation is not a model type, because it is a dimension.
4. **Sugar must compile to the canonical form and be printable back into it.** `ss.change` is allowed because it expands to `ss.Effect` and `summary()` shows the expansion. Sugar that cannot be printed back is a second language.
5. **Every addition updates this document**, including the total.

## What is deliberately absent

Each of these was proposed by at least one framework in the landscape and is not in the table above. The reasons are in [best-practices/principles.md](../best-practices/principles.md).

| Absent | Instead |
|---|---|
| A standalone DSL | Python objects |
| YAML/JSON/spreadsheet authoring | the same, with the IR as the compile target |
| Eight named flow kinds | two, plus a route that owns the denominator convention |
| A general reaction primitive `A + B -> C + D` | two named kinds the compiler can transform |
| `Overwrite` adjustments | multiplicative only |
| A junction state kind | a branching arrow |
| A separate metapopulation model class | a spatial dimension |
| A fifth object for protective tools | `ss.Effect` |
| A class lattice per intervention type | keyword arguments |
| A separate rule language for triggers | `ss.Expr` over results |
| Mandatory ontology identifiers | optional `ontology=` |
| Positional or integer state references | names, checked |
| Symbolic analysis as a headline feature | opt-in, with a stated give-up condition |
| Budget optimization and optimal control | `cost=` now, optimization later |
| A separate specification per paradigm | `method=` |
