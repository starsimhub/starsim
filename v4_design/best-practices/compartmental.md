# Compartmental (deterministic ODE)

## Recommendation

1. **A purely compartmental model runs as an ODE by default.** `method='auto'` picks the simplest, fastest representation that can run the model exactly, and prints what it picked and why.
2. **The ODE solution must be exact, not approximated with homogeneous agents.** This is the largest single change from Starsim.
3. **The model text is the same in every paradigm.** For a simple model the run method is a free choice: `sim.run(method='ode')`, `sim.run(method='abm')`.
4. **The textbook model needs no mixing object.** With no network given, mixing is homogeneous and `beta` is the classical transmission rate.
5. **Non-exponential dwell times become Erlang sub-compartments, generated by the library.**
6. **Print the equations.** `sir.equations()` shows the ODE system with parameter names, so the user can check it against the one in their head.
7. **Build the model as a graph of states and transitions before running it.** The library generates the right-hand side from the graph; the user never writes a derivative function.

## Why

### Starsim's compartmental limit is approximate and one-directional

From the [Starsim review](../approaches/starsim.md):

> **The compartmental limit is approximate, not exact.** Starsim can be run in an ODE-like configuration, but it gets there by simulating agents homogeneously, not by solving equations. It cannot produce the deterministic solution, and paradigm conversion is therefore one-directional.

This is the thing to fix, and [population-and-mixing.md](population-and-mixing.md) is how: homogeneous mixing (the default when no network is given), `ss.MixingPool(n_contacts=c)`, and age-structured mixing pools all have exact ODE forms. There is nothing left to approximate.

### One specification, several run methods, already demonstrated

[epipack](../approaches/epipack.md) shows it can be done: the same list of process tuples goes to a numeric ODE integrator, a Gillespie simulator, or a network simulator. Its review: "Whatever else is uncertain about this project, 'the same model text can be deterministic, stochastic, and network-simulated' is not."

[camdl](../approaches/camdl.md) does ODE, chain-binomial, and Gillespie from one source. [odin](../approaches/odin.md) does ODE and discrete-time stochastic, with `initial()` shared and `deriv()` versus `update()` selecting the paradigm. [EpiModel](../approaches/epimodel.md) offers three paradigms with one input vocabulary but three separately written models, which its review calls "the honest baseline this project is trying to beat: same vocabulary *and* same model text."

### And several separately written implementations is the alternative

[MEmilio](../approaches/memilio.md) has `ode_sir`, `ode_seir`, `ode_secir`, `ode_secirvvs`, `ode_secirts`, `ode_seair`, `ode_seirdb`, `ode_seirv`, `ode_mseirs4`: nine ODE model classes, plus IDE, LCT, GLCT, SDE, metapopulation, and ABM families. From its review: "MEmilio is the cost estimate for *not* having a lingua franca… this library is a large, well-funded, multi-year effort, and the paradigm coverage was bought by writing each one separately."

## The proposal

### The textbook SIR

```python
sir = ss.Disease(
    infection = ss.transmission('S -> I', beta=0.3),
    recovery  = ss.progression('I -> R', dur=10),
)

sim = ss.Sim(sir, unit='day')
sim.run()
```

```text
method: ode (every part of this model has a compartmental form)
mixing: homogeneous (no network given)
```

No mixing object, no `/N`, no run method. With no network given, mixing is homogeneous with one contact per unit time, so `beta` here is the classical transmission rate. `sir.equations()` prints the system with the parameter names, not their values:

```text
dS/dt = -beta * S * I / N
dI/dt =  beta * S * I / N - I / dur
dR/dt =  I / dur
```

`equations()` is a method of the disease, not the sim, because a sim may hold several diseases.

When the contact rate should be its own number, give a mixing pool, and `beta` becomes the probability of transmission per contact:

```python
sir = ss.Disease(
    infection = ss.transmission('S -> I', beta=0.03),
    recovery  = ss.progression('I -> R', dur=10),
)

sim = ss.Sim(sir, networks=ss.MixingPool(n_contacts=10), unit='day')
sim.run()
```

```text
>>> sir.equations()
dS/dt = -n_contacts * beta * S * I / N
dI/dt =  n_contacts * beta * S * I / N - I / dur
dR/dt =  I / dur
```

Nothing about the disease declaration is ODE-specific. `total_pop=` gives the size of the population represented and scales the compartments. `n_agents=` is the number of simulated agents; giving it is one of the ways to ask for an agent-based run. To run this same model with agents, for example to study elimination, say so: `sim.run(method='abm')`.

Compare what the frameworks require. **camdl** needs a `transitions` block with hand-written total propensities including `/N`. **odin** needs `deriv()` and `initial()` per compartment. **summer2** needs `add_infection_frequency_flow` versus `add_infection_density_flow`. **[EpiModel](../approaches/epimodel.md)** needs a `deSolve` derivative function whose returned vector is positional and must match the order of `init.dcm()`: "an unchecked coupling between two separate function calls, and a good argument for named transitions."

### What `auto` does

`method='auto'` is the default. If every part of the model has an exact compartmental form, it runs as a deterministic ODE. Otherwise it runs with agents. A model becomes agent-based by containing something agent-based (an individual-level network such as `ss.RandomNet`, `n_agents=`, a per-agent function or attribute), or because the user asked for it. `auto` never approximates. The choice and the reason are printed, as above.

Asking for `method='ode'` explicitly on a model that does not fit exactly is also allowed: the library uses the standard approximation where one exists and says so in one line. See [paradigm-conversion.md](paradigm-conversion.md).

### The model is a graph first

[odin](../approaches/odin.md) topologically sorts the user's equations; [SimInf](../approaches/siminf.md) resolves a dependency graph; [summer2](../approaches/summer2.md) builds a `networkx` DAG and hands it to JAX; camdl lowers the model text to a flat intermediate form. From the summer2 review: "summer2's `networkx` DAG, odin's topological sort, and camdl's IR are three routes to the same requirement. Whatever the lingua franca's surface syntax, the model must become a graph before it becomes a computation."

In the lingua franca this needs no separate step and no new language. A disease is already a set of `ss.State` and `ss.Transition` objects. At build time (`sim.init()`) the library reads them and generates the function that computes the derivatives. It is ordinary Python throughout.

The ODE method should use JAX for larger models, for the same reason summer2 does: speed, and **automatic differentiation of the whole model with respect to its parameters**, which gives gradient-based [calibration](calibration.md) and sensitivity analysis at no extra effort. For small models plain `scipy.integrate.solve_ivp` is enough, and it is used when there is no gradient to compute.

### Dwell times

An ODE means exponential dwell times, and, per finding 7 of the [landscape review](../approaches/README.md#cross-cutting-findings), nearly every framework assumes this without saying so.

```python
ss.progression('I -> R', dur=ss.days(10))             # exponential, rate 1/10 per day (printed)
ss.progression('I -> R', dur=ss.days(10), stages=3)   # Erlang: I1, I2, I3 generated
```

The second is camdl's `via erlang` and [MEmilio](../approaches/memilio.md)'s entire LCT model family, as one keyword. The generated sub-compartments appear in `sir.describe()` and are summed in the results, so `n_I` still means what the user meant.

A distribution that is not exponential or Erlang has no exact ODE form. Under `auto` such a model runs with agents, where the dwell time is sampled directly. If the user asks for `method='ode'`, the library fits Erlang stages and says so:

```python
sir = ss.Disease(
    infection = ss.transmission('S -> I', beta=0.3),
    recovery  = ss.progression('I -> R', dur=ss.weibull(c=1.4, scale=ss.days(8))),
)
ss.Sim(sir, unit='day').run(method='ode')
```

```text
method: ode
  note: recovery has a Weibull dwell time, approximated by 2 Erlang stages (mean 7.3 days kept; std 5.2 instead of 5.3 days)
```

`stages=k` sets the number of stages by hand. `approx=False` turns the note into an error for users who want only exact runs.

### Equations, and a numeric R0

[epipack](../approaches/epipack.md) gets the ODE system in LaTeX, the Jacobian, the fixed points, and the eigenvalues at the disease-free state because the model is symbolic data. [EoN](../approaches/eon.md) has `estimate_R0(G, tau, gamma)` from the network side.

We keep the part that every user benefits from:

```python
sir.equations()   # the ODE system, with parameter names
sir.R0()          # optional: a numeric R0 from the next-generation matrix, for simple models
```

`equations()` is how a user checks that the model they wrote is the model they meant, and it works for any model with an ODE form. `R0()` is useful for textbook examples and teaching, and few real disease models need it, so it is a small numeric helper and not a headline feature. The rest of epipack's symbolic analysis (Jacobians, fixed points) is not part of v1; epipack's own review notes that it "is tractable for a few compartments and intractable for a stratified model".

### Branching and the transition table

Branching is a multi-destination arrow ([model-structure.md](model-structure.md)), not [Atomica](../approaches/atomica.md)'s zero-residence-time junction compartment. Three views show the structure of a model:

```python
sir.transitions   # the table of transitions
sir.describe()    # the resolved model as text, with every guessed default marked
sir.diagram()     # the state-transition diagram
```

Printing `sir.transitions` shows Atomica's transition matrix: a square compartment × compartment grid with the driving parameter in each cell. Its review is right that this "is, at a glance, the flow diagram. It also makes structural errors visible: an empty row is an absorbing state, an empty column is unreachable."

The names `plot()`, `summary()`, and `to_df()` are kept for results, as in Starsim.

### Counts or proportions

Results are counts by default. A proportion is a result with a denominator, and the denominator is the user's choice, because it is not always the whole population:

```python
S, I, R = ss.states('S I R')
infection = S >> I @ 0.3 * I
recovery  = I >> R @ ss.days(10)

sir = ss.Disease(infection, recovery, frac_infected = I / (S + I))   # in a result a bare state is its count; in a rate it is exposure
```

`I.prev` is the common case, the fraction of the whole population in `I`. This is [MIRA](../approaches/notes.md#askem-model-representation-amr--mira)'s `counts_to_dimensionless`, done as an output option and not as a property of the model: the dynamics are the same either way.

## Trade-offs

- **Individual-level networks have no exact ODE form.** Under `auto` a model with `ss.RandomNet` or `ss.MFNet` runs with agents. Asked for explicitly, `method='ode'` uses the standard approximation (contact rates between groups) and says so; the result is a coarser model, not the same one. See [paradigm-conversion.md](paradigm-conversion.md). If someone wants the exact network result, they can use agents.
- **Erlang expansion multiplies compartments**, and stacked with [stratification](stratification.md) it multiplies fast. Report the compartment count.
- **Per-agent continuous heterogeneity has no exact ODE form.** `rel_sus = ss.lognorm_ex(mean=1, std=0.3)` makes the model agent-based under `auto`. Under an explicit `method='ode'` it is supported where possible, by binning the attribute into a few groups, with a one-line note giving the bins. Where no sensible binning exists the run stops and names the attribute.
- **Defaulting to ODE means a user who wanted stochastic agents has to say so.** The printed `method: ode (...)` line is what makes this visible, and `method='abm'` or `n_agents=` is the one-keyword fix.
- **JAX is a heavy dependency** for what is, in the small case, `scipy.integrate.solve_ivp`. Ship both; use SciPy when the model is small and there is no gradient to compute.

## Rejected

- **A separate compartmental model class** (MEmilio, EpiModel's `dcm`). The paradigm is a run method.
- **Making the user write the derivative function** (EpiModel's `new.mod`, MetaCast's subpopulation function). Positional, unchecked, unstratifiable.
- **Requiring `/N` in the rate expression** (camdl, SimInf, flepiMoP, EMULSION). It follows from the mixing.
- **Requiring a mixing object for a well-mixed model.** Homogeneous mixing is the default.
- **Agents as the default for every model.** Starsim's base is agent-based, but a purely compartmental model run with homogeneous agents is slower and noisier than the ODE it stands for. The default is the simplest representation that works.
- **Symbolic analysis as a headline feature** (epipack's Jacobians and fixed points). Useful for textbook models and rarely needed for real ones. Equations are printed; the rest is left out of v1.
- **Fixed model structures** ([`epidemics`](../approaches/epidemics.md)). A defensible choice for its audience, made in the knowledge that "users cannot create new links between compartments". Not ours.

## Open questions

- **Should `auto` run a model with one non-Erlang dwell time as agents, or as an ODE with fitted stages?** The rule as written says agents, because `auto` never approximates. A user with an otherwise simple model may be surprised by the switch. The printed reason should name the transition that caused it.
- **How many groups does binned heterogeneity get by default,** and is the bin count worth exposing as an option or only through an explicit stratification?
- **Where is the line between SciPy and JAX?** Model size, presence of a gradient request, or simply whether JAX is installed.

Two earlier questions are closed. A model on a random network that needs the exact network result is run with agents; the ODE form of a network is the standard approximation and nothing finer. Mixing methods within one run (some transitions as discrete random events inside an ODE) is deferred; see [paradigm-conversion.md](paradigm-conversion.md).
