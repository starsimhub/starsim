# Compartmental (deterministic ODE)

## Recommendation

1. **The compartmental limit must be exact, not an approximation reached with homogeneous agents.** This is the largest single change from Starsim.
2. **The paradigm is a run-time choice, not a property of the model.** `sim.run(method='ode')`.
3. **The state space is shared across paradigms; only the dynamics operator differs.** odin's factoring, and it is right.
4. **Non-exponential dwell times become Erlang sub-compartments, generated by the compiler.**
5. **Ship the symbolic payoff — R₀, the Jacobian, the ODE system in LaTeX — as opt-in, and say when it gives up.**
6. **Compile, do not evaluate.** The model becomes a graph before it becomes a computation.

## Why

### Starsim's compartmental limit is approximate and one-directional

From the [Starsim review](../approaches/starsim.md):

> **The compartmental limit is approximate, not exact.** Starsim can be run in an ODE-like configuration, but it gets there by simulating agents homogeneously, not by solving equations. It cannot produce the deterministic solution, and paradigm conversion is therefore one-directional.

This is the thing to fix, and [population-and-mixing.md](population-and-mixing.md) is how: once β is per-contact and the route supplies contacts, `ss.Homogeneous(n_contacts=c)` and `ss.MixingPool(matrix=M)` have exact ODE forms. There is nothing left to approximate.

### One specification, several backends, already demonstrated

[epipack](../approaches/epipack.md) is the existence proof — the same list of process tuples goes to a numeric ODE integrator, a Gillespie simulator, or a network simulator. Its review: "Whatever else is uncertain about this project, 'the same model text can be deterministic, stochastic, and network-simulated' is not."

[camdl](../approaches/camdl.md) does ODE, chain-binomial, and Gillespie from one source. [odin](../approaches/odin.md) does ODE and discrete-time stochastic, with `initial()` shared and `deriv()` versus `update()` selecting the paradigm. [EpiModel](../approaches/epimodel.md) offers three paradigms with one input vocabulary but three separately written models — which its review calls "the honest baseline this project is trying to beat: same vocabulary *and* same model text."

### And several separately-written implementations is what it costs not to

[MEmilio](../approaches/memilio.md) has `ode_sir`, `ode_seir`, `ode_secir`, `ode_secirvvs`, `ode_secirts`, `ode_seair`, `ode_seirdb`, `ode_seirv`, `ode_mseirs4` — nine ODE model classes, plus IDE, LCT, GLCT, SDE, metapopulation, and ABM families. From its review: "MEmilio is the cost estimate for *not* having a lingua franca… this library is a large, well-funded, multi-year effort, and the paradigm coverage was bought by writing each one separately."

## The proposal

### The same model, run as ODE

```python
sir = ss.Disease(
    infection = ss.transmission('S -> I', beta=0.05),
    recovery  = ss.progression('I -> R', dur=ss.days(10)),
)

sim = ss.Sim(sir, mixing=ss.Homogeneous(n_contacts=10), n=1000)
sim.run(method='ode')
```

The generated system, which `sim.equations()` will print:

```
dS/dt = -10 · 0.05 · S · I/N
dI/dt =  10 · 0.05 · S · I/N - I/10
dR/dt =  I/10
```

Nothing about the disease declaration is ODE-specific. `n=1000` is a population size, not an agent count — in ODE mode it scales the compartments, in ABM mode it is the number of agents, and it means the same thing either way.

Compare what the frameworks require. **camdl** needs a `transitions` block with hand-written total propensities including `/N`. **odin** needs `deriv()` and `initial()` per compartment. **summer2** needs `add_infection_frequency_flow` versus `add_infection_density_flow`. **[EpiModel](../approaches/epimodel.md)** needs a `deSolve` derivative function whose returned vector is positional and must match the order of `init.dcm()` — "an unchecked coupling between two separate function calls, and a good argument for named transitions."

### Order-independent, compiled

[odin](../approaches/odin.md) topologically sorts; [SimInf](../approaches/siminf.md) resolves a dependency graph; [summer2](../approaches/summer2.md) builds a `networkx` DAG and compiles to JAX; camdl compiles to a flat IR. From the summer2 review: "summer2's `networkx` DAG, odin's topological sort, and camdl's IR are three routes to the same requirement. Whatever the lingua franca's surface syntax, the model must become a graph before it becomes a computation."

The compiled ODE backend should target JAX for the same reason summer2 does: JIT for speed, and **automatic differentiation of the whole model with respect to its parameters**, which makes gradient-based [calibration](calibration.md) and sensitivity analysis free rather than a project.

### Dwell times

An ODE means exponential dwell times, and — per finding 7 of the [landscape review](../approaches/README.md#cross-cutting-findings) — nearly every framework assumes this without saying so.

```python
ss.progression('I -> R', dur=ss.days(10))                    # → rate 1/10
ss.progression('I -> R', dur=ss.erlang(k=3, mean=ss.days(10)))  # → I1, I2, I3 generated
```

The second is camdl's `via erlang` and [MEmilio](../approaches/memilio.md)'s entire LCT model family, as one keyword. The generated sub-compartments appear in `sim.summary()` and are aggregated in the results, so `n_I` still means what the user meant.

An arbitrary distribution with no Erlang or hyper-Erlang fit is where the ODE backend stops:

```text
CapabilityError: 'recovery' has dwell time Weibull(k=1.4, λ=8 days).
  The ODE backend represents dwell times as exponential or Erlang/hyper-Erlang stages.
  Options: dur=ss.erlang(k=2, mean=ss.days(8))   [closest Erlang fit, prints the discrepancy]
           method='ide'                          [memory kernel, exact, slower]
           method='abm'                          [sampled directly, exact]
```

### The symbolic payoff, opt-in

[epipack](../approaches/epipack.md) gets the ODE system in LaTeX, the Jacobian, the fixed points, and the eigenvalues at the disease-free state — that is, the epidemic threshold, derived — because the model is symbolic data. [EoN](../approaches/eon.md) has `estimate_R0(G, tau, gamma)` from the network side.

```python
sir.equations()   # rendered
sir.R0()          # derived from the next-generation matrix, symbolically where possible
sir.jacobian()
```

R₀ is the number the audience actually asks for, and once the model is a graph with a declared route it is computable rather than derived by hand. But epipack's warning stands: "Fixed points and eigenvalues do not scale. Symbolic analysis is tractable for a few compartments and intractable for a stratified model — the very cases where the derivation is hardest to do by hand." So: attempt it, fall back to numerical, and say which one you got.

### Junctions, branching, and the tabular view

Branching is a multi-destination arrow ([model-structure.md](model-structure.md)) rather than [Atomica](../approaches/atomica.md)'s zero-residence-time junction compartment. And the compartmental paradigm gets the best free projection:

```python
sir.to_df()
```

which is Atomica's transition matrix — a square compartment × compartment grid with the driving parameter in each cell. Its review is right that this "is, at a glance, the flow diagram. It also makes structural errors visible: an empty row is an absorbing state, an empty column is unreachable."

## Trade-offs

- **Exactness constrains the route vocabulary.** `ss.SexualNet` has no ODE form. That is a fact about concurrent partnerships, not a limitation of the implementation, and the compiler must refuse rather than approximate — see [paradigm-conversion.md](paradigm-conversion.md).
- **Erlang expansion multiplies compartments**, and stacked with [stratification](stratification.md) it multiplies fast. Report the compartment count.
- **Agent-level continuous heterogeneity has no exact ODE representation.** `rel_sus ~ lognorm(1, 0.3)` needs either a discretizing dimension or a mean-field approximation, and either way the summary must say which.
- **JAX is a heavy dependency** for what is, in the small case, `scipy.integrate.solve_ivp`. Ship both; use the simple path when the model is small and there is no gradient to compute.

## Rejected

- **A separate compartmental model class** (MEmilio, EpiModel's `dcm`). The paradigm is a run method.
- **Making the user write the derivative function** (EpiModel's `new.mod`, MetaCast's subpopulation function). Positional, unchecked, unstratifiable.
- **Requiring `/N` in the rate expression** (camdl, SimInf, flepiMoP, EMULSION). It is the route's job.
- **Compartmental as the default paradigm.** Starsim's base is agent-based, the default should stay agent-based, and ODE should be one keyword away.
- **Fixed model structures** ([`epidemics`](../approaches/epidemics.md)). A defensible choice for its audience, made in the knowledge that "users cannot create new links between compartments". Not ours.

## Open questions

- **What is the exact ODE limit of a random network?** For a Poisson-degree network regenerated each step, `Homogeneous`. For a static network with degree heterogeneity, it is a pair approximation and [EoN](../approaches/eon.md) names the ladder. The compiler needs to know which case it is in.
- **Does the ODE backend need a stochastic sibling in the same call?** [Catalyst.jl](../approaches/notes.md#modelingtoolkitjl--catalystjl)'s per-reaction `PhysicalScale` — importation as a jump, transmission as an ODE, in one system — is the sharpest version of this idea in any field. See [paradigm-conversion.md](paradigm-conversion.md).
- **Count versus proportion formulations.** [MIRA](../approaches/notes.md#askem-model-representation-amr--mira) has `counts_to_dimensionless` as a named operation, and nobody else names it. Worth having, probably as an output option rather than a model property.
