# Stochasticity and reproducibility

## Recommendation

1. **Keep Starsim's per-distribution RNG streams.** Adding or reordering a module must not perturb another module's draws.
2. **Keep common random numbers, and make the CRN contract explicit and checked** rather than documented in comments.
3. **Key common random numbers on declared agent attributes, not only on a slot index** — Vivarium's formulation generalizes better.
4. **Adopt camdl's factored run identity**: model, parameters, config, scenario, and fit hashed separately.
5. **Content-address runs.** An identical re-run should be a cache hit, and results should not be silently overwritable.
6. **State the RNG semantics of an array draw in the specification.** odin's rule is the kind of ambiguity that produces silently wrong models.
7. **Convergence is a claim to be checked**, not an assumption.

## Why

### Per-distribution streams

From the [Starsim review](../approaches/starsim.md):

> Every distribution is an `ss.Dist` object with **its own random number generator**, seeded from the sim's `rand_seed` plus a hash of the distribution's fully-qualified name. Consequences: adding a module, or reordering modules, does not change the random draws of the other modules. Distributions can be drawn from independently and in any order without correlating.

Nothing else in the review does this. [EpiModel](../approaches/epimodel.md) uses base R's global stream, so parallel runs are reproducible but "not identical to serial ones". [odin](../approaches/odin.md)/dust has per-particle streams but not per-distribution.

### Common random numbers

Starsim implements CRN at the agent level: each agent holds a `slot`, and a per-UID draw is generated by hashing `(seed, draw index, slot)`, so "agent 7's uniform for a given decision is the same in the baseline and intervention scenarios, regardless of how many other agents drew from that distribution."

The payoff is large: "Paired scenario comparison therefore differences out most of the Monte Carlo noise, and small intervention effects are detectable with far fewer replicates."

Three other frameworks reach for the same thing by different routes. [camdl](../approaches/camdl.md) pairs scenarios at the run level so "a counterfactual differs only where the intervention does". [`epidemics`](../approaches/epidemics.md) uses `withr` to preserve seeds across scenario runs "so that differences between scenario runs are attributable to the scenario rather than to the RNG". [Vivarium](../approaches/vivarium.md) configures it declaratively:

```yaml
randomness:
    key_columns: ['entrance_time', 'age']
```

Vivarium's version is the more general formulation, and its review says why: "Starsim keys on an agent slot; Vivarium keys on `['entrance_time', 'age']` — configurable, and meaningful across populations that are not the same set of agents. The latter generalises better to comparing scenarios with different population sizes, which is a case Starsim's slot scheme handles awkwardly."

Meanwhile [EpiModel](../approaches/epimodel.md), [odin](../approaches/odin.md), [epipack](../approaches/epipack.md), and most others have no CRN at all, "so paired scenario comparison is unavailable and small intervention effects need many replicates."

### The CRN contract has an edge, and it is undocumented

Also from the Starsim review, and this is the part to fix:

> This is a genuine design achievement and also the source of some of the framework's sharpest edges: sampling without replacement, joint draws, and any operation that cannot be written as a per-agent inverse-CDF fall outside the CRN guarantee, and the code has to mark those paths explicitly.

The implication drawn there: "In a language with declared transitions, the condition can be checked."

### Run identity

[camdl](../approaches/camdl.md) is alone in the review on this:

> camdl enforces this through a factored run identity: model hash, params hash, config hash, scenario hash, fit hash. A reviewer asking "is this a structural change or a parameter sweep?" reads the level hashes rather than diffing files… Runs are content-addressed by their exact inputs, so an identical re-run is a cache hit rather than a recomputation, and results cannot be silently overwritten.

Its review calls this "a reproducibility mechanism the lingua franca should copy outright", and the [approaches README](../approaches/README.md) agrees: it "solves a problem every framework in this review has and none of the others addresses".

## The proposal

### Keep the machinery; change the interface

```python
sim = ss.Sim(sir, rand_seed=1)
```

Underneath, unchanged from Starsim: one RNG per distribution, seeded by hashing its name; per-agent CRN by hashing `(seed, draw_index, key)`.

Changed: the key is declarable, following Vivarium.

```python
ss.Sim(sir, crn_key='slot')                     # default: Starsim's current behavior
ss.Sim(sir, crn_key=['birth_date', 'sex'])      # Vivarium's: stable across population sizes
ss.Sim(sir, crn_key=None)                       # off
```

`slot` stays the default because it is fast and it is right whenever the populations being compared are the same agents — which is the common case. The attribute-keyed form is what makes "compare a 10,000-agent run to a 100,000-agent run" meaningful.

### Check the contract

Because [transitions are declared](model-structure.md), the compiler knows which draws are per-agent inverse-CDF and which are not:

```text
>>> sim.summary()
common random numbers: on (key='slot')
  ✓ infection, recovery, mortality — per-agent, CRN-safe
  ! network.rewire — samples without replacement; CRN does not hold across scenarios
    paired differencing will include Monte Carlo noise from this draw
```

This is [camdl](../approaches/camdl.md)'s capability-check discipline applied to CRN: name the limitation rather than leaving it in a comment. It is the difference between a guarantee and a habit.

### The array-draw rule

[odin](../approaches/odin.md) specifies this carefully and it is worth copying verbatim into our spec:

> `x[] <- Normal(0, 1)` gives every element its own draw, while `a <- Normal(0, 1); x[] <- a` gives every element the same draw.

Its review: "That distinction is exactly the kind of thing that is ambiguous in most frameworks and silently wrong in some."

Our version:

```python
dur = ss.lognorm(mean=ss.days(10))      # in a transition: one draw per agent
p   = ss.lognorm(mean=0.1).rvs()        # one draw, shared
```

The rule: **a distribution in a per-agent slot draws per agent; a distribution evaluated to a scalar draws once.** Written down, not inferred.

### Run identity

```text
>>> sim.hash()
model=8f3a21  pars=c47e90  config=1b6d55  scenario=vaccine  seed=1
```

Four hashes, computed from the declared model, the resolved parameter values (including the provenance of any fetched data — see [parameters-and-distributions.md](parameters-and-distributions.md)), the execution configuration, and the scenario. Comparing two runs:

```text
>>> ss.diff(run_a, run_b)
model:    same
pars:     beta 0.05 → 0.08
config:   same
scenario: baseline → vaccine
```

That is the question every reviewer of a modeling analysis asks — *did the model change, or did the numbers?* — answered without diffing files.

Content-addressing follows: a run whose four hashes already exist is a cache hit, and writing a different result to an existing identity is an error rather than an overwrite.

### Convergence is checked

camdl ships diagnostics that "almost nothing else in the review offers": a Richardson dt-convergence audit distinguishing "it ran" from "it converged", particle-filter health (ESS, τ²), prequential scoring, and convergence gates between fit stages.

The two that generalize cheaply:

```python
sim.check_dt()      # halve dt, re-run, report the change. A discrete-time model that
                    # moves when dt halves has not converged.
sim.check_reps()    # is n_reps enough for the quantity being compared?
```

For a stochastic model, `check_reps()` is the more commonly needed one and nothing in the review offers it. With CRN on, the required replicate count for a paired comparison is often an order of magnitude lower, and saying so concretely is worth more than a warning in the documentation.

### The seed is not the reproducibility story

Worth stating explicitly in the documentation because it is widely misunderstood: a fixed seed makes a *run* reproducible; the four hashes make an *analysis* reproducible. A paper reporting `rand_seed=1` and nothing else has reported almost nothing.

[SimInf](../approaches/siminf.md)'s `package_skeleton()` — a command that turns a model into a distributable, installable, citable R package — is the other end of this and its review is right that it is "trivial once the model is data". `ss.export(sim, 'my_analysis/')` producing a directory with the model, the resolved parameters, the data references, the environment, and a runnable script is the same idea and should exist.

## Trade-offs

- **CRN constrains how sampling can be implemented.** Anything not expressible as a per-agent inverse CDF falls outside the guarantee. Accepted, now checked and reported rather than assumed.
- **Attribute-keyed CRN is slower than slot-keyed** (a hash over several columns rather than one integer). Default to slot; offer the other.
- **Hashing the model requires a canonical form.** Two textually different but semantically identical models should hash the same, which needs a normalizer. That normalizer is also what makes prose→model determinism testable ([principles.md](principles.md)), so it is not an extra cost.
- **Content-addressed caching surprises people** when they expect a re-run to actually re-run. camdl's answer — the cache hit is reported, and there is a `--force` — is the right one.

## Rejected

- **A single global RNG stream** (EpiModel). Adding a module changes everyone's draws.
- **Reproducibility by seed alone.** Necessary, wildly insufficient.
- **CRN as an implementation detail.** It changes what a comparison means; it belongs in the summary.
- **Per-particle streams as the only mechanism** (dust). Right for particle filters, insufficient for paired scenarios.
- **Making CRN mandatory.** Some analyses want independent replicates, and a user comparing structurally different models across which agent identity is meaningless should be able to turn it off.

## Open questions

- **What is the CRN guarantee when the population differs between scenarios?** Vivarium's attribute keying answers part of this; births, deaths, and migration mean the agent sets diverge over time even from a common start. There is probably a statable guarantee ("agents alive at the divergence point retain their draws") that is worth writing down.
- **Does CRN survive paradigm conversion?** camdl pairs at the run level for compartmental backends; Starsim pairs at the agent level. Comparing an ODE baseline to an ABM intervention is not a paired comparison in any useful sense, and the summary should probably say so.
- **Deterministic flows inside a stochastic model** — camdl's `deterministic()` and `overdispersed()` annotations, and [Catalyst.jl](../approaches/notes.md#modelingtoolkitjl--catalystjl)'s per-reaction `PhysicalScale`. This is really a [paradigm-conversion](paradigm-conversion.md) question, but the RNG implications (which streams exist, what CRN means) belong here.
