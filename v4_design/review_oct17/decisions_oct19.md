## New from the October 19 work

12. **An all-zero data series in the default goodness of fit** (DF21). PD2 chose to divide it by the model's mean, so it adds 1 when the model has any and 0 when it has none (before, its raw counts swamped the fit: 420 deaths a week). The reviews' own proposal; the alternatives were the other series' scale (wrong when units differ) or raising. The term is flat for any nonzero model, so the spec advises a likelihood or weight to push harder toward zero. Recommendation: keep.
13. **A fresh seed per evaluation in agent fits** (W13 follow-up, with the note you asked for in [the PD2 worklog, section 6](worklogs_oct19/WORKLOG_pd2.md)). In short: any unbiased likelihood estimate at each point gives the exact posterior (pseudo-marginal MCMC, Andrieu and Roberts 2009), and a surrogate such as Optuna's TPE pools nearby points, so spreading runs is at least as good as replicating, as you said. But Starsim fits use the same seed at every point, so neighbors share their chance and pooling cannot average it out: the fit finds the optimum of one seed's realization, whose error falls only as 1/√(number of seeds). With one run a point, a fresh seed per evaluation would let the pooling average the chance (at the cost of a jagged objective for local methods such as Nelder-Mead). `test_epimodel_fit` at one run a point lands at 23.4% against the 30% target (four runs 33.8%, ten 27.2%). Recommendation: a fresh seed per evaluation for Optuna fits of stochastic models, the same seed for local methods.

16. **Item 18 B′ was built and reverted again** (agent PB; [worklog](worklogs_oct19/WORKLOG_pb.md), patches in [worklogs_oct19/pb_patches/](worklogs_oct19/pb_patches/)). It met the SIR goals (contact SIR peak −0.1% daily, −0.7% weekly; count SIR +0.2%, −0.8%; Reed-Frost's chance of no further case 0.142 against the exact 0.131, from 0.010; the textbook kr6 peak 1,516 against the ODE's 1,557, from 1,171, though still 7 days late), but moved other ordinary models the wrong way: cholera's peak +1.6% to +11%, a capped rate +2% to +15%, an SEIR with `dur=` −1.3% to −12%. The cause is structural: anyone who enters a state during a step is recorded once before their first exit draw, so with `r·dt/(1+r·dt)` each state's clock runs slow by `1 + r·dt`; a single-rate SIR hides it. A prototype of another convention, C (every rate read at the start of the step, every exit at its end, exit chance `r·dt`), is better at a daily step on the hard cases (SEIR E −2%, I 0%; cholera +1.5%; kr6 2.6 days late) and settles ST4 exactly, but a fixed 10-day SIR goes from −0.4% to −7.4% and a weekly SEIR stays poor. Agents are unchanged for now (the documented bias stands). Options: (a) leave as is, documented; (b) B′ anyway; (c) C; (d) a short design of the agents' step order first, measured on one fixed set (contact and count SIRs, SEIR, cholera, a capped rate, a fixed dwell, Reed-Frost, kr6) at daily and weekly steps, before choosing. Recommendation: (d), since two conventions have now each fixed some cases and broken others.
17. **How entry times are kept only when read** (item 9 follow-up; agent PMEM, [worklog](worklogs_oct19/WORKLOG_pmem.md)). Memory is now 48 bytes per agent (from 81; `test_laser_memory` passes). Recommendation: keep, and add a declared alternative only if the heuristic misfires.
