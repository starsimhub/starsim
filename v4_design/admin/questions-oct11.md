# Questions from the October review

Questions I would have asked while revising `best-practices` and `design`, with the guess I went with in each case. Everything here is already applied in the documents; each item says what to change if the guess was wrong.

## Decisions most worth a second look

1. **Capitalization rule.** I used Starsim's existing habit as the rule: modules and base classes are CamelCase (`ss.Disease`, `ss.State`, `ss.Transition`, like `ss.Dist` and `ss.Rate`), and the concrete pieces you put inside a module are lowercase (`ss.transmission`, `ss.par`, `ss.modify`, `ss.outcome`, like `ss.normal` and `ss.perday`). Is that the rule you want, or should everything inside a model be lowercase, including `ss.state` and `ss.transition`? Products are still `ss.Vaccine` / `ss.Test` / `ss.Treatment`. [CK: this is tricky ... i do like that rule in general, although the boundary is fuzzy. i think of lowercase objects as 'small' things and camelcase objects as 'big' things; plus 'common' things are lowercase and 'base classes' are camelcase. so i thiiiink you've gotten it right, but we'll probably get feedback from coauthors.]
2. **One transition class, with the kind read from the rate.** Your question about why transmission and progression are separate led me to merge them: `S >> I @ beta * I` is contact-mediated because the rate mentions a state, and `I >> R @ gamma` is spontaneous because it does not. `ss.transmission(...)` and `ss.progression(...)` survive as shorthand for the two-line form. Good, or do you want the two kinds to stay visibly distinct? [CK: ah ... this is good.]
3. **A bare number after `@` is a rate, not a duration.** Your sketch had `recovery = I >> R @ dur` with `dur = 10`. I could not find a safe way to let both `@ 0.05` (rate) and `@ 10` (duration) be bare numbers, so `@ 10` means a rate of 10 and a duration has to be typed (`@ ss.days(10)`) or given by keyword (`dur=10`). Would you rather a bare number after `@` be a duration, or have the transmission case always carry the state (`@ beta * I`) so that a bare number in a spontaneous transition can be a duration? [CK: no, i think rate is the right choice.]
4. **`ss.states('S I R')` needs the names.** `S, I, R = ss.states()` cannot know how many states to return or what to call them without inspecting the caller's bytecode. I used the `sympy.symbols` idiom. Inside a class body the names could be picked up automatically (`S = ss.State()`), which the docs allow. [CK: damn, ok. let's do `S, I, R = ss.states(3)` as the short form then.]
5. **`ss.Disease(infection, recovery)` takes names from the variable names**, by looking in the caller's namespace (your "pull from namespace to DRY"). That replaces `ss.compose`. It is slightly magical; the fallback name is `S_to_I`. OK? [CK: yes]
6. **Default time unit.** Your sketch says a bare `beta = 0.05` "defaults to ss.perday", so the docs say: bare numbers take the sim's unit, and if nothing sets one, days are assumed and printed. Starsim's own default is years. Which should it be? [CK: let's do unitless timesteps if nothing has any units. as for whether should use years or days ... hm i guess days, since very few diseases would use dt=ss.years(1). but we can probably infer from the start and stop. and/or, we can do what most of the other models in the review do.]
7. **`describe()` and `diagram()`.** You said `plot()`, `summary()`, and `to_df()` should be about results. I named the model-structure versions `sir.describe()` (resolved model as text), `sir.diagram()` (picture), `sir.equations()`, and `sir.transitions` (the table). `describe()` clashes mildly with pandas, where it means summary statistics. Alternatives: `sir.show()`, `sir.spec()`, `sir.disp()`. [CK: show() clashes with matplotlib and disp() is already heavily used in starsim. i think `sir.describe()` is fine.]
8. **`ss.modify` instead of `ss.Effect`.** You did not like the name "Effect" and thought the mechanism too restrictive. The simple case is now `ss.modify(hiv.rel_trans, multiply=2.0, where=syphilis.active)` with any named quantity as a target, and everything more complex is an ordinary `step()` method, presented as a normal way to work and not as an escape hatch. Is `modify` the right word? (`ss.scale`, `ss.adjust`, and a method `hiv.rel_trans.modify(...)` were the other candidates.) [CK: i like modify]
9. **`sim.methods()` instead of `capabilities()`.** It matches the `method=` keyword. You suggested "runtime" or "integrator"; I avoided those because the table also covers agent-based runs. [CK: ooh, how about `sim.solvers()`? and then `solver=` instead of `method=`]
10. **Approximation policy.** I read your three comments together as: `method='auto'` never approximates (it picks a method that fits); asking explicitly for a method the model does not fit (for example `method='ode'` with a sexual network) *is* the explicit request to approximate, so the library uses the standard approximation and prints one line saying what it did; it stops only when no sensible approximation exists. `approx=False` turns approximations into errors. Is asking for the method explicit enough, or do you want a separate `approx=True`? [CK: explicit method + warning is good, maybe could have approx=True to silence the warning.]
11. **`ss.Compartments` for vectors and environmental reservoirs.** This is new. The first draft had `ss.Continuous` and left vector-borne transmission as its biggest open problem. I replaced both with a module whose states are counts (a mosquito population, a water reservoir), using the same transition syntax and living in the same sim as agents, plus `I.n` (the count in a state) usable in any rate. It answers your "agent-based analogue of `ss.Continuous`" question and the malaria/wastewater case, but it is a second kind of population and I would like your reaction before it hardens. [CK: i'm a bit confused by it, and definitely don't like the name since S, I, R are also compartments. i'm willing to be convinced, but am not yet.]
12. **`stratify` returns a new model** and leaves the original untouched, so that stratified and unstratified versions can be compared and re-running a notebook cell does not stratify twice. Starsim objects are usually mutated in place; say if you would prefer that here. [CK: yes: have an `inplace=True` default kwarg.]
13. **No required `writes` / `requires`.** You pointed out that people forget them and that they drift. I dropped them as requirements and replaced them with observation: `sim.what_modifies(x)` reports the modifiers on a quantity and the modules seen writing to it during a run. Enough? [CK: ...yes, i think so. i don't know how useful `what_modifies()` would be, but we can potentially keep it now and drop it later if it doesn't get used.]
14. **Eligibility without `ss.age`.** Conditions are either a function of the sim (`lambda sim: sim.people.age > 65`, as in Starsim now) or built from the real objects when you have them in scope (`(ppl.age > 65) & ~sir.vaccinated`), which works because an uninitialized state array builds a lazy condition instead of evaluating. This avoids a Polars-style column vocabulary, at the cost of one piece of magic (arrays behave differently before and after `init`). Acceptable? [CK: yes, the polars columns thing is the one thing i hate about it!]
15. **Default goodness of fit is normalized RMSE**, following your suggestion, with likelihoods optional. That makes ABC the natural default for stochastic compartmental models (it only needs a distance), which matches your hunch about that regime. Optuna remains the choice for expensive agent-based models. [CK: as i noted somewhere else, i think RMSE might be too restrictive ... if there is a sensible nonparametric default to pick instead, that might be more robust to realistic epi noise.]
16. **`ss.compare_models([sim_sir, sim_seir], data=df)`** is in v1 as you hoped. I shortened your `ss.calib_compare(..., against=data)`; say if you prefer your spelling. [CK: i like your version]

## Smaller choices

17. **`networks=`, not `mixing=`.** You were unsure; Starsim's keyword wins the tiebreak, and mixing pools already go there. [CK: ok]
18. **No `ss.Homogeneous`.** With no network, mixing is homogeneous and `beta` is the textbook rate, which answers your "what would this be without `ss.Homogeneous`" question. A contact rate is set with Starsim's `ss.MixingPool(n_contacts=10)`. [CK: ok]
19. **`total_pop` and `n_agents`** (Starsim's names) instead of the first draft's `n` and `n_agents`. [CK: ok]
20. **`ss.per` stays.** The first draft renamed Starsim's `per` to `rate`. I reverted that as an unnecessary rename; say if you actually wanted it. [CK: keep starsim's]
21. **Starsim's distribution names** (`ss.lognorm_ex`, `ss.nbinom`) replace the first draft's `ss.lognorm` and `ss.neg_binomial`. `ss.erlang` is dropped in favor of `ss.gamma` with an integer shape or `stages=`. [CK: i think we might want ss.erlang if it's very heavily used, but you tell me if ss.gamma is the same thing.]
22. **`capacity=`** is the keyword for "a number of doses" as opposed to `coverage=` (a fraction). Starsim's `treat_num` calls this `max_capacity`. [CK: ok]
23. **`ss.change(target, at=[...], by=[...])`**: `at=` takes dates, years, or durations since the start (not `days=`); `by=` is a multiplier relative to baseline and `to=` an absolute value. [CK: ok]
24. **Boolean transfers** are written `ss.transfer(vaccinated=True, ...)` instead of `'no -> yes'`. [CK: ok]
25. **Dict tuple shorthand dropped.** The first draft's `dict(infection=('S -> I', 0.05))` needed context rules to tell a transmission rate from a recovery rate, and they misfire (SIRS). The two-line constructor form is just as short. Starsim's `dict(type='sir', ...)` for library models is unchanged. [CK: ok]
26. **Queued updates, named phases, and derived ordering are gone**; Starsim's ordered loop is the mechanism, mutual dependence between modules is allowed, and the one thing kept is that transitions out of the same state inside one module are resolved jointly (competing hazards), so that listing order inside a disease does not bias results. Deferred removal (`request_death`) is kept. [CK: ok]
27. **Hybrid per-transition methods** (some transitions as discrete jumps inside an ODE run) are deferred. You said you did not follow the original text and leaned "no"; the open question is now written in plain words in case it is wanted later for elimination studies. [CK: ok]
28. **Symbolic analysis** is cut back to `equations()` plus an optional numeric `R0()` for simple models. Jacobians and fixed points are gone. [CK: actually i think we might want jacobians if they help with calibration ... is this what jax provides? we want to be able to replicate a lot of camdl's machinery for this (though definitely not all of it).]
29. **Strictness.** The first draft of `design` was written in a strict specification voice, with hard limits and many unsuppressible errors. I softened it toward "guess and print" throughout, kept numbered error codes, and removed the codes for mechanisms that no longer exist. If you would rather drop the numbered codes or the MUST/SHOULD language altogether, that is a mechanical pass. [CK: leave it for now]
30. **File rename.** `design/14-ir.md` is now `design/14-model-spec.md`, because you asked not to talk about compilers and "intermediate representation" is compiler language. `prompts.md` still refers to the old name, since it is a historical record. [CK: ok]

## Questions raised while revising individual documents

These came up in the detailed rewrites. Each is applied as stated and marked as open in the document named.

### Transitions and states (`design/03`, `best-practices/model-structure.md`)

31. **Sinks in the operator form.** `I >> None @ ss.peryear(0.1)` works, because the typed value handles the `@`, but `I >> None @ 0.1` cannot work in Python (`None @ 0.1` is evaluated first). The docs say to use `ss.death(...)`, `ss.Transition(I, None, rate=0.1)`, or `(I >> None) @ 0.1`. Would you rather have a named sink object? [CK: yes, i proposed `ss.null` before, but maybe `ss.sink` is better? though for births it's a source not a sink ... `ss.ether`? kidding, but it's funny.]
32. **`p=` is always a branch probability.** A probability per period is written `rate=ss.probperday(0.1)`. This removes the first draft's rule that `p=` meant timing or a split depending on the number of destinations. [CK: ok]
33. **`init`**: a value below 1 is a fraction and above 1 a count; the remainder goes to the first declared state; `init_prev` seeds through the infection transition, so it lands in `E` for an SEIR. [CK: the user should be able to specify the state distribution, but yes by default the remainder goes to the first declared state.]
34. **Total population** in a rate or a ratio is a sum of states (`N = S + I + R`, then `I / N` or `Iv.n / N.n`); there is no `ss.N`. Do you want a shorter built-in handle? [CK: no i think it's ok]
35. **Rates must be linear in bare states.** `beta * I` and `beta * (I + 0.5 * A)` are exposure through the networks; `I ** 2` or `I / (I + K)` is an error telling you to use counts (`I.n`). [CK: ok]
36. **Flow results are named exactly as the transition** (`sim.results.sir.infection`, `cum_infection`), and Starsim's standard `new_infections`, `cum_infections`, and `prevalence` are still generated for any disease with transmission. Or should every flow be `new_<transition>`?  [CK: this is tricky, `infections` definitely reads better, but the exact match is also nice. would `sir.infection` and `sir.new_infections` be the same thing? i think we might need to try out a few different things and see what feels most natural.]
37. **Names come from variable names** for modules and parameters as well as transitions (`sir = ss.Disease(...)` gives `sim.results.sir`). [CK: ok]

### Run methods (`design/12`, `best-practices/paradigm-conversion.md`, `compartmental.md`)

38. **A lognormal (or other non-Erlang) dwell time under `method='auto'` makes the model agent-based**, because auto never approximates. That may surprise someone writing an SEIR with a lognormal incubation period who expected an ODE. The alternative is to let auto use Erlang stages and say so. [CK: yes, auto should be able to use erlang]
39. **Networks other than sexual networks under an explicit `method='ode'`** are approximated by homogeneous mixing at the network's mean contact rate within whatever groups the model declares. The stage count for a dwell-time approximation is `round((mean/std)^2)`. [CK: ok]
40. **`methods()` table shape**: one "stochastic" column for ctmc/tau/binomial/sde, rows per ingredient, and a footer saying what auto would choose. [CK: ok]
41. **`ss.Compartments` inside an agent-based sim** advances deterministically unless given `method='binomial'`. It is passed with `ss.Sim(modules=[cholera, water])` and made per-patch with `.stratify(patch=...)`. A count used in another module's rate lines up on shared dimensions and sums over the rest. [CK: ok]
42. **In a compartmental run, `sim.people.age` returns the midpoint of each age group**, and a condition whose threshold cuts through a group (age > 65 with a 60 to 69 group) stops with a message. Should it approximate instead? [CK: hm ... no, i think stopping is right]

### Interactions and interventions (`design/07`, `design/08`, `best-practices/composition-and-effects.md`, `interventions.md`)

43. **Where `ss.modify` goes**: in `connectors=` for biology and `interventions=` for policy; the only difference is where in the loop its condition is evaluated. [CK: ok]
44. **Direct writes when modifiers exist.** Reading a modifiable array gives the effective value; assigning to it sets the base; `.base` reads the base explicitly. Two overlapping `set=` modifiers: the later one in loop order wins, with a warning. [CK: i don't understand this but ok]
45. **Write tracking** for `sim.what_modifies()` is on by default (`ss.Sim(track_writes=False)` to turn it off). One agent guessed on and one off; I went with on. [CK: i think off is right ... i don't really like this feature anyway, but we can experiment with it.]
46. **`ss.modify` also takes `when=` (a function of the sim) and `min_duration=`**, for triggers such as closing schools above a case threshold. [CK: this feels a little fragile to me.]
47. **Coverage semantics**: routine delivery (only `start`/`stop`) offers each person once, when they first become eligible; rounds (`years=`, `interval=`) offer every eligible person once per round. `coverage=` may be a function for a per-person probability. When `capacity=` runs out, recipients are chosen at random; a `priority=` keyword is listed as open (stisim's ART prioritizes by CD4 and care-seeking, which suggests it is needed). [CK: ok]
48. **Reordering across module types**: `sim.loop.insert()` is extended to accept a module, so that screening can be placed after transmission. Is that the way you would want to do it? [CK: ok]
49. **The ANC example** uses `on=anc.visit` for the event-triggered form, and a boolean array plus a `due_test` flag in the `step()` form. There is no general "schedule for the next time X happens" helper yet; that is listed as open. [CK: ok]
50. **Products**: efficacy dict keys are `acquisition`, `transmission`, `mortality`, or any transition name. `ss.Treatment` with a scalar efficacy is a cure probability through the recovery transition. `take=`, `doses=`, `ss.exp_decay`, and `ss.linear_decay` from the first draft are dropped; `waning=` takes a duration, a function, or a time series. [CK: ok]
51. **`ss.transfer` that needs a new dimension** is passed to `stratify()` as an extra keyword (`tb.stratify(resistance=['DS', 'MDR'], acquired=ss.transfer(...))`). [CK: ok]
52. **Results indexing in triggers.** Starsim results are preallocated for the whole run, so "the last 7 days" is `new[sim.ti - 7:sim.ti]`, not `new[-7:]`. Should results get a "so far" view? [CK: i don't think this is super important, but ... sure, if it's not too hard]

### Calibration (`design/13`, `best-practices/calibration.md`)

53. **Normalized RMSE** is RMSE divided by the mean of the data series. Parameters whose bounds span a factor of ten or more are searched on a log scale. [CK: ok, though see above about RMSE]
54. **Staged fitting** is `sim.calibrate(method=[...])`, a list of stages, because `stages=` now means Erlang sub-stages on a transition. A stage that fails to converge stops the sequence and returns the last good fit. [CK: hm, ok, don't fully follow]
55. **A likelihood** can go on an outcome (`ss.outcome(..., likelihood=ss.nbinom(...))`) or be passed to `calibrate()`. The convention is that the model value is the mean and the user supplies the rest. [CK: ok]
56. **`ss.compare_models`** holds out the last 25% of each data series by default, fits on the rest, and scores the predictions; `folds=` gives rolling-origin evaluation. [CK: ok]
57. **Fitting `beta` times contacts**: a product in `pars=` moves the first factor and holds the others fixed. [CK: ok]

### Other

58. **Commuting** is specified as a share of time spent in the destination patch (`away=0.4`), with no sub-step scheduling. Starsim has no `ss.hours`, so the first draft's `at=ss.hours(8)` could not have worked as written. [CK: ok]
59. **Determinism** is softened from "bit-identical across machines" to "identical on the same machine and versions; identical across machines is a goal". [CK: ok]
60. **`design/09` generates `prevalence` automatically** (as Starsim does), so a user-declared `prevalence = I / N` replaces the default. [CK: ok]

61. **The vocabulary did not get smaller.** `design/17-vocabulary.md` now counts 133 public names against the first draft's 134: 93 `ss.` names (58 already in Starsim 3.7.2, 35 new) and 40 method and attribute names. The predicate names, `ss.Effect`, `ss.Continuous`, and the closure vocabulary went, but calibration, comparison, and delivery keywords came in. If the total matters to you, the mobility models (`ss.gravity`, `ss.radiation`, `ss.stouffer`, `ss.competing_destinations`) and the reproducibility helpers (`ss.diff`, `ss.export`, `sim.check_reps`, `sim.crn_report`) are the first candidates to cut or defer. [CK: i think this is ok for now]
62. **Error catalog.** `design/15-errors.md` went from 87 codes to 48 (31 errors, 8 warnings, 9 notes), and "never suppressible" is gone. Several mistakes now raise plain `TypeError`/`ValueError` without a code. [CK: ok]
63. **`sim.summary()` versus Starsim.** Your comment used `summary()` for results; Starsim 3.7.2 actually has `sim.summarize()` and a `sim.summary` attribute, so `design/01` uses those names. The `best-practices` documents still say "`summary()` is about results" in two places as shorthand. [CK: yes, summarize() is right]

## Fact-check of `approaches/starsim.md` and `approaches/camdl.md`

Checked against Starsim 3.7.2, stisim 1.7.0, and the camdl source. Corrected:

- **Starsim**: the release date of 3.6.0; the custom `SIR` example (it raised an error without `reset=True`, and the label was wrong); the claim that `self.foo = 3` raises on a module (it does not; undeclared *parameters* are rejected); `ss.State` listed as an existing class (it is not; the array classes are `BoolState`, `BoolArr`, `FloatArr`, `IntArr`, `IndexArr`); the `ss.prob` conversion formula; `Infection.infect()` not `Disease.infect()`; the arguments of `RoutineDelivery` and `CampaignDelivery`; the description of `ss.Dx` (a table of result probabilities, not sensitivity and specificity) and `ss.simple_vx` (no waning); the loop order (rescaling step added); the counts of module categories and time classes; and the worked STIsim example (`sti.ART` has no `years=` argument, the module is `syph`, and `Syphilis` has no `.active`).
- **camdl**: the license (MIT, not Apache-2.0); the version (0.1.0-alpha, not 0.2.x); parameter kinds (no `time`; there are `instant` and `duration`); `fit.toml` (one method per file now; named stages are refused at load); the run-identity levels (model, config, params, scenario, seed, with fits identified separately); and the observation example (it needed a `covers =` line to compile).

Not verified: the count of first-party Starsim disease models, and camdl's claim that every backend and method combination is tested.

One consequence for the design: several things the first draft described as "Starsim already does this" are proposals, in particular `ss.State` as a single class and sensitivity/specificity on diagnostics. The revised documents say "proposed" where that matters.
