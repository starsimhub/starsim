# Switching demos

One test per framework in the comparison set (plus Starsim 3), each the five-step demo from `v4_design/review_oct17/README.md` §1 written in that field's terms: bring the model in, describe it, fit it, ask the policy question, and run it in another paradigm or at another scale. Each is scaled down to run in seconds and asserts the acceptance criterion from the table "Acceptance: the thirteen switching demos" in `v4_design/review_oct17/implementation.md`, against the original framework's reference numbers, which are stored in each file as constants with a note of which switching report (`v4_design/review_oct17/switching/<seat>.md`) they come from. Every demo starts as `xfail`, with the reason naming what blocks it (finding numbers from `v4_design/review_oct17/new-findings.md` and `findings/`); the goal of the implementation plan is that all thirteen pass, at which point each `xfail` is removed. They are not part of the main suite (`cd tests && pytest test_*.py` does not collect them); run them with `cd tests && pytest switching` (add `-rxX` to see each reason). Tests that need the lingua_franca_design repo or R with reticulate are skipped when those are not available (see `tests/paths.py` and `tests/test_r.py`).
